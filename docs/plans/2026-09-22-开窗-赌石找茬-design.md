# 新小游戏设计 · 「开窗」（赌石 · 找茬开盲盒）

> **状态**：设计已由作者确认（模块形态＝独立模块、首版＝完整版、名字＝「开窗」）
> **目标仓库**：`tutan-cc/tianshu` · 分支 `JL` · 基线 `2c002c9`（v1.31）
> **一句话**：在夜市地摊上相玉 —— 拖放大镜在皮壳上**找茬**（找裂、找注胶、看松花蟒带）→ 出价 → 一刀切开见分晓。

---

## 一、为什么做它

现有 12 类玩法里，**财富线只有"运气"没有"眼力"**：

| 现有财富玩法 | 性质 |
|---|---|
| 🎟 刮刮乐（¥20/张） | 纯运气，点完即知，无技术含量 |
| 股市波段（六日买卖） | 有判断，但一次性、只在 D8 节点 |
| 麻将自由局 | 有技术，但慢（5–10 分钟）、且是零和对手 |

「开窗」补的是**快节奏 + 可归因**的缺口：一局 3 块石头、每块 20–30 秒；输了知道**为什么**输（"我漏了那道裂"），而不是"手气不好"。这正是重复游玩的动机来源。

## 二、玩法设计

### 2.1 一局的形状

```
一局 = 3 块石头，每块三段式：

① 相玉（找茬）25 秒
   ├─ 拖放大镜在皮壳上搜索（圆形取景，2.2× 放大 + 边缘暗角）
   ├─ 左键点击 = 打标：命中特征 → 记入「料单」；空点 → −2 秒 + 放大镜抖动
   └─ 「照一照」提示：次数 = 1 + ⌊智慧/20⌋（上限 3），在随机位置闪一次探照
② 出价
   ├─ 三档：¥50 / ¥200 / ¥1000（钱不够的档位置灰 + 写明原因）
   └─ 或「不买，走人」（摊主嘲讽一句，不亏不赚）
③ 开窗（切）
   ├─ 切割线动画 → 断面展开 → 露出种 / 色 / 内部裂纹
   └─ 结算：净收益 = 真实价值 − 出价 → 进财富 + toast + 台账
```

### 2.2 找茬的两类特征

| 类别 | 特征 | 作用 |
|---|---|---|
| **涨**（想找到） | 松花（绿点簇）、蟒带（成带纹路） | 提示内部有色，提升估价 |
| **垮**（想避开） | **裂**（细线，最致命）、绺（浅裂）、注胶痕（半透明胶斑）、假皮（色界生硬） | 贬值；**没找到的照样在切开后扣钱** |

**核心因果**：出价时你只知道"你找到的"。未发现的裂 → 切开后真实价值按比例打折。**眼力直接换算成钱**，这就是"找茬"作为核心动词的理由。

### 2.3 数值模型（可单测）

> **整条金钱刻度缩过两次**：¥250/450/800 →（×0.25）¥60/110/200 →（再 ×1/3）**¥20/40/70**。
> 原因见 §6.6 与 §6.7。等比缩放不改手感，只改钱的绝对大小。

```
真实价值 = base × mul(种) × mul(色) × Π penalty(每条**未发现**的垮特征)
          取整到 1

base       3–13（按皮壳 tint 微调）
mul(种)    豆 1.0 · 糯 2.0 · 冰 5.0 · 玻璃 20.0     （冰/玻璃的概率由蟒带抬高）
mul(色)    无色 1.0 · 飘花 1.6 · 阳绿 3.5 · 帝王绿 15.0（阳绿/帝王绿的概率由松花抬高）
penalty    裂 ×0.35 · 绺 ×0.80 · 注胶 ×0.60 · 假皮 ×0.05
垮特征数   0(25%) 1(35%) 2(22%) 3(12%) 4(6%)   涨特征数 0(30%) 1(50%) 2(20%)，**不重复**
成就门槛   单块净赚 ≥ ¥250（【一刀富】，实测 0.49% 的石头够得着）
```

**三档地摊档位**（按钮上是大字价格 + 档位名 + 一句白话，照麻将开局面板的三档注码排法）：

| 档位 | 价格 | 白话 | 定位 |
|---|---|---|---|
| **小料** | **¥20** | 蒙头货 · 全凭手气 | 贴着 E[价值]，盲出小亏；看出一个信号就够本 |
| **中料** | **¥40** | 有松花就值这个价 | 强读档：要"双sign 且没发现裂"才赚 |
| **大料** | **¥70** | 摊主压箱底的那块 | 全押档：完美读料 ≈ 打平，靠尾巴翻身 |

**实测分布**（80000 块蒙特卡洛，当前刻度）：

```
E[价值] = 18 · p50 = 6 · p90 = 42 · p99 = 193 · max = 2880
E[价值|蟒带] = 25 · |松花 = 23 · |蟒+松 = 32 · |蟒+松+无裂 = 65
盲出期望：¥20 → −2 · ¥40 → −22 · ¥70 → −52   （三档全负 = 庄家占优）
完美读出价 ¥70 的期望 ≈ −5（打平区，靠尾巴翻身）
```

**为什么首档是 ¥20**：**对齐刮刮乐**（¥20/张）—— 这是全游戏最便宜的一注，
与"地摊上随手赌一块石头"的体感一致。参照系：刮刮乐 ¥20 · 消耗品 ¥30–60 ·
麻将最低注码 ¥50 · 新档初始财富 ¥10。最初版的 ¥250 要跑六七个节点才敢开一局，属定价事故。

**经济不变量（已写成测试，改数值必跑）**：
1. **盲出必亏**：三档在无信息条件下的期望**全部为负**。
2. **先验一致**：`PRIOR_MID` 与实测 `E[价值]` 偏差 < 8%（改了分布/刻度忘重标 → 红）。
3. **技能有回报**：找茬命中率越高，每次出价的期望越高。
4. **不失控**：完美读料的每块期望有上限（< E[价值] 的 55%），防刷钱。

> 第 3 条的对照值与第 4 条的上限都写成**相对刻度**，所以整条刻度缩放时测试不会
> 无谓地红（第一次缩放时绝对数断言被误伤过 —— 见 §6.6）。

### 2.4 系统耦合

| 系统 | 接入方式 |
|---|---|
| 智慧 | 放大镜视野半径 + 「照一照」次数 |
| 财富 | 出价本金；钱不够则档位置灰（沿用现有 UI 语言） |
| 台账 | `S.jadeRuns` 局数 · `S.jadeNet` 累计净收支 · `S.jadeBest` 单块最高收益 |
| 成就 | 【一刀富】：单块净赚 ≥ ¥250（需要玻璃/帝王绿级的高货，文案从模块回填） |

## 三、技术方案

### 3.1 模块形态

**独立模块 `jade.js`**（ES5 IIFE，`window.Jade`），与 `breakfast.js` / `mahjong.js` 同构：

```
jade.js
├─ 1. 常量与调参区（SKINS / KINDS / TUNE / PRICES）—— 改手感只动这里
├─ 2. 纯规则 rules（无 DOM，可在 vm 里单测）
│     genStone(seed) / estimateOf(stone, found) / trueValueOf(stone) / settle(stone, found, bid)
├─ 3. 渲染 render（Canvas：皮壳纹理 / 特征 / 放大镜 / 切割动画）
├─ 4. 运行时 start / dispose / loop / 输入（鼠标 + 触屏）
└─ 5. 对外 API：version · start · isBusy · dispose · rules · debug
```

`index.html` 只放**胶水**：侧栏按钮、覆盖层容器、现金结算、成就检查（照早餐店的分工）。

### 3.2 必须同步的三处

1. **`tools/dev/stamp.js:53-56` 的文件表**要加 `{ file: "jade.js", tag: "jd" }` —— 否则会重演 `breakfast.js` 那次"文件是新的、浏览器跑的是旧的"缓存事故（该脚本头注释就是为这件事写的）。
2. `index.html` 的 `<script src="jade.js">`（排在 `breakfast.js` 之后）。
3. 改完跑 `node tools/dev/stamp.js` 重新盖章（`--check` 现在本来就是红的，顺手修好）。

### 3.3 资源复用（零新素材）

| 用途 | 复用 |
|---|---|
| 放大镜摩擦 | `sfx-lot-scratch` |
| 切石 | `sfx-mj-clack` |
| 涨 / 垮 | `sfx-stock-up` / `sfx-stock-down` |
| 夜市环境音 | `amb-alley` |
| 图标 | 先走 emoji 🪨 兜底（按钮已有 `onerror` 回退机制），不阻塞 |

### 3.4 测试

| 层 | 内容 |

## 五、风险

| 风险 | 缓解 |
|---|---|
| 三档出价被玩家算出最优解 | 隐藏参数 + 随机分布；好料概率低；未发现的裂使信息永不完全 |

| 小屏上裂纹看不清 | 桌面优先；放大镜本身是 2.2× 放大，已缓解 |
| 经济被刷崩 | §2.3 的四条不变量写成测试，改数值必跑 |

## 六、实现后记（标定过程与踩过的坑）

这一节记录**为什么最终是这些数字** —— 数值不是拍出来的，是被测试一步步逼出来的。

### 6.1 经济标定：四次翻车

| # | 症状（实测） | 根因 | 修法 |
|---|---|---|---|
| 1 | 乱买只亏 ¥18/块，庄家优势薄得像没有 | 三档价格与价值分布没对齐 | 按分位重新定档 |
| 2 | **刷钱机**：E[价值] 265 时乱买每块 **+65** | 给涨特征接了条件概率后，种水色期望被抬高，底价区间没同步缩 | 底价 60–260 → 40–150 |
| 3 | **刷钱机（第二次）**：所有打法（含"命中率 0%"）每块都能赚 105–157 | **估价偷看了隐藏底价** —— 判断准得离谱 | 估价改成只吃"先验 + 找到的特征"（见 §6.2） |
| 4 | **死按钮**：¥1200 档连"完美读料"都是 −519 | 全押档定得比高货期望还高，靠技术永远够不着 | 抬高高货乘数（玻璃 12→20 / 帝王绿 9→15）+ 全押档降到 ¥800 |
| 5 | **劝退机**：出价率掉到 1–5%，玩家 95% 时间只能"走人" | 首档 ¥280 高于 E[价值] 太多，估价几乎覆盖不了 | 首档降到 ¥250（贴着 E[价值]，一个信号就能下场） |

> 五次里有三次是蒙特卡洛探针发现的，两次是写成测试之后被测试抓住的 ——
> 这印证了一件事：**这类玩法的正确性几乎全在数值上，靠玩是玩不出来的**。

### 6.2 最隐蔽的一个 bug：估价偷看了答案

`estimateOf` 最初的基准是 `st.base`（这块石头的**真实底价**）。后果：估价准得离谱，
"照着估价出价"稳赚 —— 命中率 0% 的策略每块还能赚 105。

修法有三条，缺一不可：
1. 基准换成**先验常数** `PRIOR_MID`（总体期望），估价只被"找到的特征"修正；
2. 乘数取**实测的条件期望比值**（蟒带 1.342 / 松花 1.292），而不是拍脑袋的 1.5/1.7；
3. 写一条**结构性断言**：给 `estimateOf` 传一个"读隐藏字段就抛异常"的替身对象，
   它必须毫无反应 —— 这条测试现在锁死了这个 bug 不会复发。

### 6.3 视觉与手感（截图验收发现的）

- **切石那一刀的渲染顺序错了**：先画两半皮壳、再画断面 → 断面糊在皮壳外面，像贴了张白纸。改成**先断面、后两半**，并把断面裁在石头轮廓内。
- **镜外压暗 0.55 太狠**：整块皮壳黑成一片，玩家连"该把镜子挪到哪"都看不出来 → 降到 0.38。
- **黑乌沙太黑** → 底色抬亮一档（#3f3a33 → #4a443c）。
- **皮壳噪点太淡** → 黑 0.16 / 白 0.12，并加噪点数量到 1100：放大镜下能分辨、1× 下看不见，是找茬的甜点。
- **非搜索阶段还显示倒计时**（"正在切石却还剩 25 秒"）→ 切成"—"。

### 6.4 给无头验收留的钩子

headless 环境里 rAF 推进极慢，等 1 秒切石动画会把验收拖垮
（实测 `--virtual-time-budget 30s` 都只截在动画中途）。所以加了
`Jade.debug.cutNow()`（把动画推到终点并结算），与 `breakfast.js` 的 `debug.finishNow` 同一用途。
**它不属于规格**，只在 `debug` 里。

### 6.6 第六次翻车：首档 ¥250 不合理（刻度整体缩小 ×0.25）

**触发**：用户反馈"我找不到这个游戏"，排查时又发现 —— **新档初始财富 ¥10，而首档要 ¥250**，
新玩家一局都开不了（麻将最低注码 ¥50、刮刮乐 ¥20、消耗品 ¥30–60，都比它便宜得多）。

**为什么不能只降首档**：经济不变量要求**三档全部高于 E[真实价值]**，否则盲出就是正期望。
只把首档降到 ¥60、其余不动，等于凭空造出一个刷钱档（E=216 时出价 60 每块赚 156）。

**修法**：把**整条刻度**等比缩小 ×0.25 —— 底价区间、三档价格、先验常数、成就门槛一起动：

| 项 | 缩放前 | 缩放后 |
|---|---|---|
| 底价区间 | 40–150 | **10–38** |
| 三档 | 250 / 450 / 800 | **60 / 110 / 200** |
| E[价值] | 216 | **54** |
| 成就门槛 | ¥3000 | **¥800** |
| 取整颗粒 | 10 | **5**（刻度变小后 round10 会把低端四舍五入得面目全非：15×0.35=5.25 → 10） |

等比缩放的手感是**完全不变**的（盲出三档全负、技能梯度、出价率、走人率全部按比例平移），
验证数据：盲出 −6.3 / −56.3 / −146.3；命中率 30%→100% 时每注期望 +25.7 → +76.7；
出价率 17–21%；成就门槛在 0.4% 的石头上可达。

**附带教训**：测试里原本有三处**绝对数值**断言（完美读料上限 120、一刀富门槛 4000、
同量级下限 20）。刻度一缩，它们要么误红、要么失去意义 —— 全部改成**相对刻度**
（E 的 55%、最高档的 5 倍、PRIOR_MID 的 0.3 倍）。**凡是与"钱"有关的断言，都该以
E[价值] 或档位为基准，而不是写死元数。** 另外成就门槛也不再写死在 `index.html`，
改成从 `Jade.rules.JACKPOT_NET` 读，避免"文案说 ¥800、模块按别的数判定"的错位。

### 6.7 第七次调整：再降一档 + 换成地摊叫法

**触发**：用户要求"价格更低一点，改成更'地摊'的叫法"。

**定价**：首档直接对齐**刮刮乐（¥20）** —— 全游戏最便宜的一注，与"地摊上随手赌一块石头"
的体感一致。整条刻度再 ×1/3：

| 项 | 原来 | 现在 |
|---|---|---|
| 三档 | 60 / 110 / 200 | **20 / 40 / 70** |
| 底价区间 | 10–38 | **3–13** |
| E[价值] | 54 | **18** |
| 成就门槛 | ¥800 | **¥250**（可达率 0.49%，与最初 0.4% 的目标一致） |
| 取整颗粒 | 5 | **1**（刻度到"几元"级后，round5 会把假皮与绺的差别抹平） |

**叫法**：赌石摊上没人说"出价 60 元"，说的是"这块料"。所以三档改成
**小料 / 中料 / 大料**，按钮排成「档位名 + 大字价格 + 一句白话」（照麻将开局面板
三档注码的排法）。同时把整段文案改成摊主口吻：

| 位置 | 改前 | 改后 |
|---|---|---|
| 出价提示 | 你的判断：¥X – ¥Y。出价买下它…… | **摊主把三块料往你面前一推：「小料 ¥20，中料 ¥40，大料 ¥70 —— 挑一块？」** |
| 按钮 | 出价 ¥60 | **小 料** / ¥20 / 蒙头货 · 全凭手气 |
| 放弃 | 不买，走人 | **摇摇头走了**（摊主：「看不上？回头别后悔。」） |
| 结算 | 出价 ¥40 | 出价 ¥40**（中料）** |

**顺带修的一处命名债**：取整函数从 `round10` 改名 `roundCash` —— 刻度缩到"几元"级之后，
`round10` 实际取整到 1，名字骗人（下次改刻度的人一定会被它坑）。
