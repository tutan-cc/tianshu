## 一、先从原作逆向出它的规则（不是猜的）

参考站是 Vite + three.js 的 3D 游戏，入口页只是个登记门（要 X 用户名，无邮箱）。
真正的规则写在 `assets/main-149-k2uM.js` 里。下面这些**是从代码里读出来的事实**，不是我的推测：

| 规则 | 代码里的原话 / 常量 |
| --- | --- |
| 送达得分 | `` `Delivered! +${100*Math.min(e.streak,5)}` `` → **基础 100，连送倍率 5 倍封顶**（100/200/300/400/500） |
| 精准命中 | `Bullseye! +200` |
| 引开狗 | `Dog distracted! +200` |
| 清掉池塘 | `Pond cleared! +500` |
| 恶作剧（砸窗） | `A little mischief. +400` |
| 评级 | `perfect ? "S" : 送达率≥0.8 ? "A" : ≥0.5 ? "B" : "C"` |
| 周结构 | "Seven mornings. One week." → **7 个早晨 = 一周**，逐日结算 |
| 结算界面 | 做成一张**报纸头版**：headline / deck / byline + 送达数 / 今日分数 / 骑行时间 / 评级 + 拆解（砸窗数 / 基础分 / 速度奖励 / 本周用时） |
| 报纸机制 | 报纸有限，`Out of papers. Find a roadside bundle.` → 路边报堆补满 |
| 生命 | state 里有 `lives`，`gameOver` 后出「Paper route seeks a new recruit.」 |
| 障碍种类 | `bin child car cone crash dog drain ground miss missed newsman pickup play-ball pond pothole puddle rc-car` |
| 操作 | 拖动转向；上滑加速 / 下滑刹车；邮箱亮灯时点按投递；**第二指按住再松开 = 砸窗**；鼠标瞄准可砸别的窗 |
| 雷达 | "Read the radar" / "No stops ahead" |

**结论：核心不是「扔东西」，是「读路 + 掐时机 + 有限资源 + 主动违规换收益」。**
所以移植时这四件事一件都不能丢，否则就只剩个跑酷皮。

## 二、映射表（报纸 → 外卖）

| 原作 | 本作 | 为什么这么换 |
| --- | --- | --- |
| 自行车 | **电动车** | 外卖骑手本体 |
| 报纸 | **餐（保温箱容量）** | 一一对应：有限、会用完 |
| 路边报堆 | **取餐点 / 换电柜** | 一一对应：补满资源 |
| 邮箱亮灯 | **取餐柜亮绿灯** | 一一对应：亮灯才是你的单 |
| 砸别的窗（+400 恶作剧） | **红灯柜 = 别人的单** | 保留"读灯"判断，但把"主动破坏"换成"看错就送错" |
| 7 个早晨 | **一周 7 天班** | 一一对应 |
| 报纸头版结算 | **外卖小票结算** | 同样是"纸质凭证"，更有本行味道 |
| 狗 / 小孩 / 车 / 坑 / 水坑 / 球 / 遥控车 | 原样保留（小区里全都有） | 这些障碍本来就是中国小区的日常 |
| 池塘 | **景观池** | 一一对应 |
| 邻居走上人行道 | **遛弯的大爷** | 一一对应 |

### 关键改动一：砸窗 → 逆行（**只换时间，不给分**）

原作让玩家"主动搞破坏换高分"。外卖题材里有个更真实、也更诚实的对应物：**逆行抄近道**。

设计上刻意做成**收益与分数完全隔离**：

- 逆行（骑到对向车道）→ 路空，**速度上限 ×1.12**，能省时间
- 代价 1：对向车道有**迎面来车**，撞上 = 失误
- 代价 2：路段上有**保安**，在视野内逆行 → **罚款 ¥50 + 拦停 1.2 秒**（净亏时间）
- ⚠ **逆行期间不产生任何分数增量** —— 这句在代码里是一条硬约束，`tests/delivery.test.cjs` 有断言守着

理由：如果违规加分，游戏就在教"违规是划算的"。现在它只教你"违规能省时间，但会罚款、会被撞"——**风险和收益都如实呈现，分不从这来**。

### 关键改动二：恶作剧槽位换成正向打赏

原作 +400 那个槽位，本作填**好评打赏**：一单在「零碰撞 + 未超时 + 未洒汤」下送达 → `+400`。
另加**顺手帮带**（路边帮带点，捎快递/捎垃圾）`+200`。都是正向行为，且都要操作，不是白送。

## 三、两套投递（用户选「两者都要」）

两个动词，四种用法 —— 不做四个键，避免手忙脚乱：

| 键 | 语义 | 用途 |
| --- | --- | --- |
| `空格` | **抛出** | ① 投进亮绿灯的取餐柜格 ② 扔备餐引开追你的狗 |
| `F` | **伸手** | ① 擦身递给楼下等的顾客 ② 顺路捎上帮带点 |

### 判定三条轴（这是"手感"的全部来源）

1. **目标对不对**：柜子亮**绿灯**=你的单，亮**红灯**=别人的单（投了算送错）
2. **时机**：接近目标时 HUD 出现**收缩准星环**，绿色甜区投出 = **精准 +200**
3. **身位**：目标有左右侧，**必须骑在同一侧**（`playerX × side > 0`）才能投到

三条轴各管一件事：眼睛读灯、手指掐时机、手上控车。缺一条就退化成"见到就按"。

## 四、数值表

### 得分

| 事件 | 分值 | 出处 |
| --- | --- | --- |
| 送达 | `100 × min(连送, 5)` | 沿用原作 5 倍封顶 |
| 精准投递 / 精准递餐 | `+200` | 沿用原作 Bullseye |
| 好评打赏（零失误单） | `+400` | 填原作恶作剧槽位 |
| 引开恶犬 | `+200` | 沿用原作 |
| 顺手帮带 | `+200` | 本作新增 |
| 整班零失误（按天判） | `+500` | 沿用原作 Pond cleared 的档位 |
| 提前收工奖励 | `(标准用时 − 实际用时) × 12`，下限 0 | 对应原作 speedBonus |
| **逆行** | **0** | **硬约束，见上** |
| 送错柜 / 空抛 | `0` 且该单作废 | |
| 违规罚款 | `−¥50`（只扣钱，不动分数） | |

> 好评打赏做成"**连续 3 单精准**"而不是"每单精准就给"：每单都给的话 `+400` 会成为主要收入
> （12 单就是 +4800），压过送达本身 —— 那样"投得准"就不再是加分项，而成了唯一玩法。

### 操作窗口必须按反应时间倒推（不是凭手感给个小数）

这是本次实现**最贵的教训**：窗口宽度凭"感觉差不多"写，结果三档全都短于人能反应的时间。

巡航 = `MAX_SPEED × CRUISE` = 9000 × 0.60 = **5400 单位/秒**；1 段 = 200 单位 → **27 段/秒**。

| 动作 | 初版 | 时长 | 定稿 | 时长 |
| --- | --- | --- | --- | --- |
| 投柜准星窗口 | 16 段 | **0.59 s** | 36 段 | 1.33 s |
| 擦身递餐窗口 | 9 段 | **0.33 s** | 24 段 | 0.89 s |
| 引开恶犬 | 10 段（实现里还被写死成 8 段） | **0.20–0.37 s** | 45 段 | 1.67 s |
| 甜区宽度 | ±0.11 × 窗口 | 0.15 s | ±0.11 × 36 段 | 0.29 s |

人的"看到 → 判断 → 按键"约需 1 秒，初版三档全部低于这个数，**机制在物理上按不出来**。
现在三条底线都写成断言（引狗 ≥ 1.0 秒、投递 ≥ 0.8 秒、甜区 ≥ 60 毫秒），改小就红。

### 评级（照抄原作阈值）

`完美（全送达 + 零失误）→ S` · `送达率 ≥ 0.8 → A` · `≥ 0.5 → B` · `其余 → C`

### 两级危险（本作新增的分层）

- **碰撞类**（小孩 / 车 / 垃圾桶 / 锥桶 / 狗咬到 / 迎面车）→ **失误**，3 次当班结束
- **颠簸类**（坑 / 排水沟 / 水坑 / 球 / 遥控车 / 景观池）→ **洒汤**，该单差评（少赚，但不结束）

分两级的理由：全做成扣命太硬，全做成洒汤太软。碰撞=你的错，颠簸=路况，责任不同，惩罚也不同。

### 三种模式

| 模式 | 内容 | 时长 |
| --- | --- | --- |
| `shift` 单班 | 1 天，默认 | ~80 秒 |
| `rush` 午高峰 | 限时 75 秒，单量密集 | 75 秒 |
| `week` 一周 | 7 天连跑 | ~9 分钟 |

`practice` 自由骑行：无订单、无碰撞，纯练手感（沿用仓库的练手局约定：不结算财富）。

**入场 ¥20**（租车 + 电池），与刮刮乐 / 开窗同价。**中途退出不收费**（与开窗"收摊不吃本金"口径一致）。

## 五、技术方案

### 伪 3D 投射（用户选「追尾视角」）

沿用经典 OutRun 式路段投射，**零依赖、纯 canvas 2D、ES5**（与其它 4 个模块同构）：

```
segmentLength 200 · roadWidth 1400 · cameraHeight 900 · drawDistance 240 · fov 100°
cameraDepth = 1 / tan(fov/2) ≈ 0.84
project(p, camX, camY, camZ, depth, W, H, roadWidth) →
  scale = depth / camera.z
  screen.x = W/2 + scale × camera.x × W/2
  screen.y = H/2 − scale × camera.y × H/2
  screen.w =          scale × roadWidth  × W/2
```

`project` 是**纯函数**，单测直接喂数验算（见 §六）。

**世界单位标定**（改任何尺寸前先读）：`ROAD_W` 是**半**路宽，全路 2800 单位 ≈ 9 米
→ **1 米 ≈ 311 单位**，所有精灵的 w/h 都按这把尺子写。第一版把楼房宽度写成 340 单位
（≈1 米宽），画出来才发现整条街的楼都成了纸片。

### 伪 3D 的三个坑（都真踩过，画面上很吓人、逻辑层完全测不出来）

1. **环线必须在垂直方向闭合**。赛道是环形的，如果末端高度不是起点高度，骑过终点线时
   前方所有段的世界高度都比相机低一大截，投影落到屏幕下方被 `maxy` 全部剔除 ——
   表现为**路面整块消失、只剩最近一段，像骑进虚空**。
   修法：生成完路线后补一段把高度拉回起点（经典 outrun 里的 `addDownhillToEnd`）。
2. **弯道累积横移必须有界**。`render()` 里横移是逐段累加的（`x += dx; dx += seg.curve`），
   一个持续 n 段的弯会把 x 推到 ≈ `curve × n²/2`，而且**同向弯会叠加**。
   第一版（curve 到 ±8、单段 180 段、不交替）x 冲到 **12.9 万单位 = 路半宽的 92 倍**，
   远处路面被整个推出屏幕。现在缓弯（≤±2）+ 单段 ≤140 + 方向强制交替，实测落在 20–23 倍。
3. **精灵必须从远到近画**，且要按段裁掉山丘后面的部分，否则近处的会被远处覆盖。

### 环线赛道的两个几何约束（都是"两条规则打架"型 bug）

- **逆行线不能吃掉左侧订单**。左侧订单要求 `playerX < −LATERAL`，逆行线若画在
  `−0.15`，送左侧单就必然违规 —— "要不要违规"从一个选择变成了强制的。
  几何条件：合法区非空当且仅当 `LATERAL < −WRONGWAY_X`（现在 0.10 < 0.48）。
- **红灯柜与订单必须隔开至少一个投掷窗口**。否则红灯柜和绿灯柜会同时进入窗口，
  "投哪一个"取决于谁离得近，而不是取决于玩家有没有读灯 —— 这条判断轴就废了。

- 赛道是**闭合环线**（小区环路，本来就是这样），所以"跑完一圈 = 收工"是个自然终点，不用伪造终点逻辑
- 楼栋/取餐柜/顾客/障碍全部**程序化绘制**（不引任何素材，与 `jade.js` 同一策略）
- 路段有 `curve` / `y`（坡），所以有弯道和起伏；山坡遮挡靠 `ctx.clip()` 按段裁

### 违规与分数的隔离怎么做实

不是靠"我记得别加分"，而是结构上隔离：

```
scoreOf(kind, …)   ← 唯一的加分数入口
SCORE_TABLE = { deliver:…, perfect:…, tip:…, dog:…, help:…, clean:…, speed:… }
// 表里**没有** violation 这一项 —— 未登记的 kind 一律返回 0 分，想加也没地方加
```

单测两面夹着守：① `SCORE_TABLE` 里没有 `violation`/`wrongway` 键；
② 构造"全程逆行"与"全程顺行"两局，断言 `scoreNoSpeed` **完全相等**（时间与罚款可以不同）。

> 为了让②可测，违规相关的随机数必须走**独立的 rng**：若和主序列共用，
> 逆行分支多消耗一个随机数就会把后续所有订单的命中结果整体挪位，
> 测出来的差异是"随机序列错位"而不是逆行造成的 —— 这条不变量就永远验不出来。

### 模块约定（与其它 4 个模块一致）

```js
window.Delivery = { version, start(hostEl, opts), isBusy(), dispose(), TUNE, rules, debug }
// opts: { cash:()=>number, phys:()=>number, intel:()=>number,
//         onSettle(net, info), onFinish(sum), practice:boolean, mode, day }
// rules 是纯函数层（无 DOM），可在 vm 里整局自跑 → simulateShift 不开浏览器就出分数分布
```

**经济不变量**（`simulateShift` 蒙卡 + 相对 E[value] 断言，不写死元数 —— 上次切果写死过一次，调参后变假绿灯）：

1. 瞎送必亏：低命中 + 不掐时机 → 长期期望 < 0
2. 手熟能赚但不失控：高命中 + 掐甜区 → > 0 且**封顶**（不能出现 `zen` 那种 +380/局的印钞机）
3. 逆行不改变期望**分数**（只改变用时与罚款）

## 六、验收口径

`tests/delivery.test.cjs` —— **29 项**，跑一次约 18 秒（纯逻辑，不开浏览器）。

| 层 | 怎么验 |
| --- | --- |
| 投射数学 | `project` 喂已知输入验算：路中心段 `screen.x == W/2`；`camera.z` 翻倍则 `screen.w` 减半；`z <= depth` 返回丢弃标记；横向偏移方向 |
| 路线生成 | 同 seed 两次生成**逐段相同**（确定性）；赛道长度 ≫ 绘制距离；每天订单数 = 表里的值；危险密度随天递增 |
| **环线闭合** | 最后一段的终点高度必须回到第一段起点高度（< 1 单位）—— 守卫"骑过终点线路面消失" |
| **弯道累计横移** | 全赛道 × 24 个位置 × 整个绘制范围内，`|x|` 必须 < 30 × 路半宽 —— 守卫"远处路面被推出屏幕" |
| 判定三条轴 | 时机（窗口内/外、甜区上下沿、命中区上下沿，含边界等号）；身位（同侧/对侧、容差边界）；窗口（擦身必须比投柜窄） |
| **反应时间** | 引狗窗口 ≥ 1.0 秒、投递窗口 ≥ 0.8 秒、甜区 ≥ 60 毫秒 —— 全部由 `SEG_LEN / (MAX_SPEED×CRUISE)` 推出，不写死 |
| **两条规则不打架** | 逐张订单验"存在一个不违规的身位能命中"；红灯柜与订单间隔 ≥ 一个投掷窗口 |
| 分数 | 连送倍率 5 封顶；`SCORE_TABLE` 里没有 violation 键；未登记 kind 一律 0 分 |
| 逆行隔离 | 全程逆行 vs 全程顺行 → `scoreNoSpeed` **完全相等**；且逆行真的省时间、真的吃罚款 |
| 评级 / 赔付 | S/A/B/C 阈值边界（含送达率正好 0.8 / 0.5）；赔付阶梯单调不减、0 分不给钱 |
| 经济 | `simulateShift` 蒙卡：瞎送必亏 / 手熟能赚且单调 / 高技能相对入场费有界 / 分数不超理论上限 |
| 规则真的会触发 | 「3 次失误结束」在单日模式真能触发；一周档的失误真会截断这一周；两级危险都存在 |
| **缺常量** | `TUNE` 里被代码引用的 38 个常量必须全部存在且有限 —— 守卫 `DOG_RANGE` 那类"忘了定义、比较恒假"的静默失效 |
| 实机（无头 Chrome） | 55 项：入口/浮层可见性（`rect` 不是 0×0）/画布非空白/两套投递/三条轴各自的分支/红灯柜/逆行不加分/保安拦停/日结小票/总账算式自洽/收工释放 |

## 七、实现中逮到的问题（都是"逻辑全对但玩不了/看不见"那一类）

按发现顺序，每条都留了对应的断言或注释：

| # | 现象 | 根因 | 怎么发现的 |
| --- | --- | --- | --- |
| 1 | 赛道只有两三百段 | 把「n 段的直道」写成 `addRoad(n,n,n,…)`，段数被撑成 3 倍 | 数值探针（打印每天段数） |
| 2 | 楼房像纸片 | 世界单位标定错了：楼房宽度写成 340 单位 ≈ 1 米 | 算 `ROAD_W` 与米的换算 |
| 3 | `shift`/`rush` 里「3 次失误结束」永不触发 | 模拟里一天只掷一次碰撞，单日最多吃 1 次 | 探针里 `gameOver` 恒为 0 |
| 4 | 高技能收益撞顶、技术白练 | 赔付阶梯顶格定在 skill 0.7 就能摸到的分数上 | 探针里 0.7/0.9/1.0 期望完全相同 |
| 5 | **「引开恶犬」整个是死的** | `TUNE.DOG_RANGE` 没定义 → `d < NaN` 恒假；且实现里循环上界还写死成 8 | 浏览器验收去按那一下，`dogs` 不涨 |
| 6 | 投递/递餐/引狗全都按不出来 | 窗口只有 0.2–0.6 秒，短于人的反应时间 | 新加的"窗口时长"断言直接报出 0.59 秒 |
| 7 | **送左侧订单必然违规** | 逆行线画在 −0.15，而左侧订单要求 `playerX < −0.10` | 截图里看见送左单时"逆行中"亮着 |
