## 一、现状诊断

### 1.1 当前实现（事实）

| 位置 | 内容 |
|---|---|
| `index.html` L2216–2221 | `FIGHT_FOE_I`：4 招固定循环（直拳 9 / 连击 6×2 / 抱架 block 12 / 重拳 15） |
| `index.html` L2222–2308 | `startFight(it)`：行动力 AP=3、`guard`、`read`、`precision()`、`act()`、`endTurn()` |
| `index.html` L2276–2283 | `precision()`：**两档判定**（命中 / 未命中），命中 ×1.9，窗口 1.4s |
| `index.html` L2244–2258 | `endTurn()`：对手按 `(t-1)%4` 出招；`turn>12` 超时判 `foeHp < foeMax*0.5` |
| `index.html` L539–546 | 6 个按钮：`jab / combo / low / guard / read` + 一个 disabled 的「精准提示」 |
| `index.html` L2306 | 自动化接口 `window.__cs2.fight = {hp, foeHp, ap, turn, act, auto}` |

### 1.2 四个根因（为什么"不好玩"）

1. **意图全公开 = 零决策**。`renderFight()` 直接写「对手下一步：直拳（约 9 伤害）」，而对手是 `(t-1)%4` 的确定性循环。玩家只要背下顺序，最优解固定为「抱架 → 读招 → 低扫」，第 3 回合起就是机械执行。
2. **手操层太薄**。全局只有 `precision()` 一处手操，且只有"进绿区/没进"两档 —— 手感和玩家技术**不产生梯度**，也没有任何"手操比数值更重要"的环节。
3. **没有空间维度**。6 个招式只差 `dmg / ap / precise` 三个数，等价于「用行动力买伤害」，站位、距离、朝向全不存在。
4. **12 回合超时兜底**。`turn>12 → foeHp<50% 算赢` 这条兜底规则的存在，本身就说明伤害曲线与战斗时长没调平（详见 §7.1 的实测推算）。

### 1.3 现有可复用资产（重要：本方案 70% 是复用，不是新建）

| 资产 | 位置 | 复用方式 |
|---|---|---|
| 时机条判定 | `precision()` L2260 / `startQTE()` L1668 | 抽成公共 `judgeBar()`，支持多区间、自定义速度/时长 |
| 连打 | `startMash()` L1696 | 组合拳尾段直接接 |
| 键盘 + Canvas 手操 | `startDodge()` L1720 | `←/→/↓` 输入框架、闪避带宽度按属性缩放 |
| 7 条格斗音效 | `audio/sfx/sfx-fight-*.mp3` | **⚠ 既未接入、且文件名加载不到 → 现在整场战斗一声不响**（见 §5.0，P-1 必须先修） |
| 后巷环境音 | `audio/amb/amb-alley.mp3` | `brawl` 节点 loc=`alley`，进出战斗时 `AudioSys.amb()`（同受 §5.0 影响，现为静音） |
| 玩法图标 | `art/icons/game/fight.png` | 已有，直接沿用 |
| 打斗实拍素材 | `video/box_glove / box_ring / box_ko / chase_run / chase_end` | 关键帧微视频（§4.4） |

### 1.4 设计红线（不可违反）

1. **旧 `fight` 玩法一字不改**。11 类玩法的完整性与既有存档依赖它；新机制并行开 `fight2`。
2. **`restore()` 四层校验不可绕过**。新增状态一律走"子系统缺省补齐 + 越界夹紧"（参照 `mj*` 字段做法）。
3. **纯静态、零构建、双击即玩**不变。不引入 npm 包、不引入构建步骤。
4. **数值属性必须仍然有用**。手操决定上限，`phy / int` 决定容错窗口 —— 不能变纯动作游戏。

## 二、设计目标与分层

一句话设计：**「看得懂、猜得到、手跟得上、输了也甘心」**。

四层递进，每层可独立上线、独立验收、独立回滚：

```
L4 电影感与剧情价值   ← 观感与叙事，纯表现层，零逻辑风险
L3 真机制：距离 / 体干 / 读心  ← 深度来源，主攻方向
L2 手操核心：预判防守 + 三档判定 + 反击窗口  ← 手感来源
L1 微改：分级绿区 + 音效接入 + 连打段  ← 当天可交付
```

投入产出比：**L1 与 L4 是"低垂的果实"（合计约 1 天，观感提升最明显）；L2+L3 是主菜（约 3–4 天）**。

## 三、L1 · 微改（当天可交付，不动任何结算结构）

### 3.1 绿区三档判定

`precision()` 现为 `ok = pos>=left && pos<=left+w`。改为在绿区内再切三档：

| 档位 | 区间 | 伤害倍率 | 演出 | 音效 |
|---|---|---|---|---|
| **完美** | 绿区中央 30%（`left+0.35w ~ left+0.65w`） | **×1.9** | 白闪 + 顿帧 100ms + 伤害数字放大 | `sfx-fight-perfect` |
| **良好** | 绿区两侧 | ×1.3 | 黄闪 + 顿帧 50ms | `sfx-fight-hit` |
| **偏出** | 绿区外 | ×0.7 | 红闪 + 无顿帧 | `sfx-fight-whiff` |

> 为什么偏出不是 0：保持"每回合都在推进"，避免玩家连续 miss 后进入长达一分钟的垃圾时间。惩罚用"节奏丢失"体现，而不是"白打一回合"。

### 3.2 属性化为窗口宽度（沿用既有语义）

```
w = clamp( 14 + phy*0.8 + (bonus().window + bf.window)*100, 14, 46 )   // 现有 QTE_W 写法
完美区 = 0.30 * w      // 体魄越高，完美区绝对宽度也越大 → 体魄仍是最强成长属性
```

### 3.3 音效接入（零素材成本，**前置依赖 §5.0**）

素材早就在仓库里了 —— 7 条格斗音效 + 后巷环境音，一条都没接。在 `hitFoe()` / `endTurn()` / `finish()` 里按语义点名播发：

```js
AudioSys.play("sfx-fight-hit");      // 命中
AudioSys.play("sfx-fight-block");    // 抱架成功格挡
AudioSys.play("sfx-fight-hurt");     // 自己挨打
AudioSys.play("sfx-fight-whiff");    // 打空
AudioSys.play("sfx-fight-perfect");  // 完美判定
AudioSys.play("sfx-fight-win");      // 胜利
AudioSys.play("sfx-fight-lose");     // 失败
```

### 3.4 连打尾段

`组合拳` 命中后追加 `startMash` 风格连打（5 秒 / 目标 12 次），**连打次数决定第二段伤害**：`8 + floor(count/3)`。

> 顺带修一个**文案与实现对不上**的既有瑕疵：按钮写着「组合拳 2 行动力 · **8×2**」（L541），
> 但实现是 `hitFoe(8, "你：<b>组合拳</b>", ...)`（L2294）—— **只造成 8 点，不是 16 点**。
> 要么把实现改成两段各 8（那就和 §7.1 的调平冲突），要么把按钮文案改成「8 + 连打」。
> 建议后者：既修了文案，又顺势把连打段接进来。

## 四、L2 + L3 · 手操核心与真机制

### 4.1 战报：从"全公开"到"能读心"

| 现状 | 2.0 方案 |
|---|---|
| 「对手下一步：直拳（约 9 伤害）」 | 默认**只显示模糊意图**：「他重心前压，像是要出手」 |
| 确定性 `(t-1)%4` 循环 | 招式库 + 权重 + 状态修正（见 4.3） |
| 读招 = 受伤 −25% | **读招 = 识破并公示其"习惯/意图"2 个回合**（信息操作，不是防御 buff） |

模糊意图 → 具体招式的映射表（`读招` 后显示"他右肩垮了——重拳"）：

| 提示文案 | 实际招式 | 应对 |
|---|---|---|
| 他重心前压 | 直拳 | 按 `←` 后闪 |
| 他左右晃动 | 连击 | 按 `↓` 下潜 |
| 他抱架缩身 | 抱架（不出招） | **抢攻窗口**（此时他防高，建议低扫破架） |
| 他后撤半步 | 重拳 | 按 `←` 闪 or `↑` 迎击（红圈反击） |
| 他抬腿 | 低扫 | 按 `↑` 抬腿防 |

### 4.2 手操三要素

**(1) 预判防守**：对手出招前 0.45s（读招后 0.70s）出**红闪**提示方向，玩家按 `← / ↓ / ↑` 防守。

- 方向正确 → 完全闪避（伤害 0，体干 −6）
- 方向错误 → 硬吃（伤害 ×1.0，体干 −18）
- **什么都不按 → 硬吃且体干 −18**（不能靠"不动"躺赢）

**(2) 反击窗口**：对手重招落空/被闪避后 0.5s 内亮 **红圈**，此时任意攻击键 → **完美反击**（本次伤害 ×2.2，无视对方格挡）。

**(3) 体干条（架势）双资源制**

| 事件 | 体干变化 |
|---|---|
| 攻击命中 | 对手 −10；自己 −2 |
| 攻击被格挡 | 对手 −14（破架更有效） |
| 闪避成功 | 自己 −6 |
| 硬吃伤害 | 自己 −18（与伤害数值无关） |
| 抱架（主动） | 自己 +16 |
| 回合自然恢复 | +6 |

**体干归零 → 大硬直 1 回合**：无法行动，受伤 ×2.5。这就是「抢攻 vs 养体干」的真抉择。

### 4.3 对手 AI：招式库 + 状态机

```js
FIGHT_FOE_I2 = [
  {id:"jab",   n:"直 拳", dmg:9,  band:[1,2],   stam:10, say:"他压低重心，一记直拳。",      tell:"他重心前压"},
  {id:"combo", n:"连 击", dmg:6, x2:1, band:[1,2], stam:8, say:"他左右开弓，两下连击。",    tell:"他左右晃动"},
  {id:"guard", n:"抱 架", block:12, band:[0,1,2], stam:0, say:"他抱架缩身，护住面门。",    tell:"他抱架缩身"},
  {id:"heavy", n:"重 拳", dmg:15, band:[2],    stam:14, say:"他后撤半步——这是重拳的起手！", tell:"他后撤半步"},
  {id:"low",   n:"低 扫", dmg:11, band:[0,1],  stam:12, say:"他抬腿扫向你小腿。",         tell:"他抬腿"},
  {id:"feint", n:"虚 招", dmg:0,  band:[0,1,2], stam:0, say:"他肩膀一动——是假动作。",     tell:"他肩膀一动"},
];
```

**权重状态机**（`foeStyle` 决定权重基线，`读招` 后公示 2 回合）：

| 风格 | 特征 | 权重倾向 | 用于 |
|---|---|---|---|
| `brawler` 莽夫（花衬衫） | 抢攻、少防 | jab 30 / combo 25 / heavy 20 / guard 10 / feint 5 / low 10 | `brawl` 节点（一打二） |
| `counter` 反击型（雷姐） | 等你出招 | guard 30 / feint 25 / heavy 20 / low 15 / jab 10 | 后续拳馆节点 |
| `trickster` 老油条 | 虚招多、爱忽悠 | feint 35 / jab 20 / low 20 / guard 15 / heavy 10 | 后续 KTV 打手 |

**状态修正**（累积在对手身上，`读招` 可查）：

| 条件 | 效果 |
|---|---|
| 被打中 2 次以上 | 累计每 2 次，`feint` 权重 +10（学乖了） |
| 被低扫命中 2 次 | `heavy` 权重 +15（急眼） |
| 自己血量 < 30% | `guard` 权重 −15、`heavy` +15（收人头） |
| 读招生效中 | `feint` 权重 −20（被看穿就少使诈） |

**硬直表**：`heavy` 落空 → 1 回合硬直（不吃防）；`jab`/`combo` 落空 → 0.5 回合（半个反击窗口）；`feint` → 出手后自动后退一段。

### 4.4 距离轴与位置（空间维度）

三档站位（`band` 索引与 §4.3 的 `band` 字段**同一套编号**）：`0 = far 远 / 1 = mid 中 / 2 = close 近`，初始 `1 (mid)`。

| 玩家招式 | `band` 有效段 | 收招后位移 |
|---|---|---|
| 直拳 | `[1,2]` 中·近 | 0 |
| 组合拳 | `[1,2]` 中·近 | 进 1 段（mid→close） |
| 低扫 | `[2]` 近 | 0 |
| 重拳 | `[0,1]` 远·中 | 退 1 段 |
| 抱摔（新） | `[2]` 近（需蓄力 0.8s） | 进 1 段 |
| 后撤（新，1 AP） | `[0,1,2]` 任意 | 退 1 段 |

**打出射程 = 打空**：扣 1 体干，对手获得反击窗口。**射程外强行出招**的按钮显示 `（射程外 · 打空）` 灰字提示 —— 惩罚要可预期，不能靠玩家背表。

对手的 `band` 字段决定它只能在某段出某招，玩家用 `后撤 / 进身` 可以主动"卡"对手的招式池。**这是本方案最大的策略深度来源。**

### 4.5 电影感层（L4）

## 五、落地清单（前端照此改）

### 5.0 🔴 P-1 前置：音效库整体未生效（必须先修，属全项目缺陷）

**这不是打斗的问题，是整个音频层的静默故障 —— 但打斗是最大的受害者。**

`AudioSys.sfxFile(name)`（L938）拼的路径是 `audio/sfx/<name>.mp3`，**没有文件名前缀**。
而磁盘上 `audio/sfx/` 里 65 个文件的真实命名是 `sfx-<name>.mp3`。实测：

| 调用 | 代码拼出的路径 | 实际文件 | 结果 |
|---|---|---|---|
| `sfxFile("ui-click")` | `audio/sfx/ui-click.mp3` | `sfx-ui-click.mp3` | ✅ 唯一命名对得上的一类（UI 音效） |
| `sfxFile("fight-hit")` | `audio/sfx/fight-hit.mp3` | `sfx-fight-hit.mp3` | ❌ 404 → **完全没声音**（连 beep 都没有，见下） |
| `sfxFile("mj-clack")`（mahjong.js L3667） | `audio/sfx/mj-clack.mp3` | `sfx-mj-clack.mp3` | ❌ 404 → 被 try/catch 吞掉，**完全静音** |
| `sfxFile("bf-sizzle")` / `stock-buy` / `quiz-right` / `talk-deal` / `lot-win` … | 同上前缀 | 全部带 `sfx-` | ❌ 共 **64/65 条失效** |

> **比"回落 beep"更糟：实际是"一声都没有"。** 这点必须说清楚，否则会低估严重性：
> `sfxFile()` 的注释写"返回 false = 调用方应回落合成音"，但**它无条件 `return true`**（L944）。
> 第一声：`new Audio(404路径)` 创建成功、`play()` 返回 Promise 异步失败 → 函数已 `return true` → **回落 beep 不会触发**；
> 第二声起：`this.pool[name]` 已有这个坏元素（L937）→ 连 `new` 都不再执行 → 同样静默。
> 结论：**这 64 条音效是「永远不出声」，而不是「降级成 beep」**。
> 之所以至今没被当成 bug，是因为它不出错、不报错、不抛异常 —— 只是安静。

同一问题波及另外两层：

| 层 | 代码 | 磁盘 | 结果 |
|---|---|---|---|
| 环境音 | `amb()` L974：`audio/amb/"+loc+".mp3` | `amb-alley.mp3` | ❌ **9 条全部拿不到**，且 `amb()` 没有回落分支 → **这一层是彻底静音** |
| BGM | `bgm()`：`audio/bgm/"+mood+".mp3` | `calm/city/dark/night/tense.mp3` | ✅ 这 5 条命名正确，**正常** |

> **为什么一直没被发现**：`sfxFile()` 的设计意图是"优先文件、缺失回落到程序化合成"（L917 注释明说这是刻意设计，为了素材没到位时游戏不哑）。
> 但如上所述，**回落分支实际上永远不会被触发** —— `return true` 写在 `play()` 结果未知之前。
> 于是 **73 个素材文件（64 条 sfx + 9 条环境音）** 的加载失败既不出声、也不报错、也不告警，全部静默消失。
> 麻将那条 `mj-clack` 更隐蔽：调用侧还额外套了 try/catch，连唯一的"没声音"线索都被吞掉。

**对打斗的直接影响**：现在这一场 `brawl` 一打二，**没有一次打击音、没有一次格挡音、没有后巷底噪**，
只有 `AudioSys` 的程序化 BGM 在响。这解释了为什么"打起来不燃" —— 一半是机制，另一半是它根本没声音。

**修法（改 3 个函数，不动任何调用点）**：给加载函数加"带前缀变体"回落 —— 与 `playVO()`（L1932/L1941）已有的 `real → tts` 双路径回落是同一个套路，项目里已有先例：

```js
/* ① sfxFile：先试原名，再试 sfx- 前缀变体 */
const cands = [ "audio/sfx/"+name+".mp3" ];
if(name.indexOf("sfx-") !== 0) cands.push("audio/sfx/sfx-"+name+".mp3");
/* ② amb：audio/amb/"+loc+".mp3 → audio/amb/amb-"+loc+".mp3 */
/* ③ bgm：audio/bgm/"+mood+".mp3（命名本就正确，顺手统一走同一套候选逻辑） */
```

**同时必须修掉那个"假的返回值"**：`sfxFile()` 不能在 `play()` 结果未知时就 `return true`。
最小改法是**用同步探测决定候选**：给每个候选建 `Audio`，在 `onerror` 里把它标成 `bad` 并**从 pool 里删掉**，
这样调用方的回落分支（`if(!this.sfxFile(...)) this.blip(...)`，L956 起已有 4 处）才真正有意义。
否则修完路径，问题只是"从没声音"变成"没声音但不报错"，兜底依旧是摆设。

**⚠ 顺序很重要**：这一步（P-1）必须排在打斗 2.0 之前。否则 §3.3 接的 7 条 `sfx-fight-*` 一样会静默失败 ——
到时候你会以为"音效加了但没感觉"，其实是压根没响，而且**不报任何错**。

**验收**（三条都必须能听见，不能只看代码）：

1. `brawl` 战斗里命中 = 实音（`sfx-fight-hit`），格挡 = 实音（`sfx-fight-block`），不是哔哔声
2. 后巷节点能听到 `audio/amb/amb-alley.mp3` 的底噪（现在完全没有环境音）
3. 麻将暗杠/补杠有"啪"的一声（现在静音，见 mahjong.js L3664 `gangClack`）

**顺带建议**：修完后加一条**素材存在性巡检单测** —— 遍历 `媒体清单.json` 里每个登记路径做 `Test-Path`，
纳入 `run-all-tests.ps1` 的 logic 层。这类"路径写错但不报错"的问题会反复发生，只有巡检能拦住。

### 5.1 五个必须知道的坑

> **坑 1 · 音效文件名带 `sfx-` 前缀**（= §5.0 的调用侧视角）
> 修完 §5.0 后两种写法都能响，但**新代码请统一写带前缀的全名** `AudioSys.play("sfx-fight-hit")`，
> 与 `媒体清单.json`（L1414+ 登记的 `audio/sfx/sfx-fight-hit.mp3`）保持一致，别再制造第三种命名。
> 注意：写错名字**不会报错、也不会回落 beep，只是彻底没声音**（原因见 §5.0）。写音效时听不到，先怀疑名字。

> **坑 2 · DOM id 不能复用**
> 旧 `fight` 覆盖层已占用 `fightBtns / fightFoe / fightNum / fightBar / fightZone / fightCur / fightLog`，
> 且 L2305 有 `document.querySelectorAll("#fightBtns .mbtn")` 的**全局绑定**。
> `fight2` 必须全部另起 id（`fight2Btns / fight2Foe / ...`），否则两套玩法的按钮会互相抢事件。

> **坑 3 · 存档新字段必须补齐缺省**
> 新手状态（`pos / stam / foeStam / combo / stun / style`）**不进存档**（每场战斗重置）→ 最安全。
> 只有"跨节点的战斗成长"（如 `S.fightStyle` 熟练度、`S.fightFlags`）才进存档，且必须在 `restore()` 的子系统补齐里给默认值，
> 否则旧档直接被判坏档、玩家进度丢失（这是项目已有的血泪约定，见 `调试与跳转说明.md` 末尾）。

> **坑 4 · 键盘监听要成对摘除**
> `precision()`（L2282）与 `startDodge()` 都是 `window.addEventListener("keydown", ...)`。
> fight2 有 4 套输入（预判/反击/蓄力/连打）同时挂键盘，**必须在切换阶段时 `removeEventListener`**，否则会出现"按一次空格触发三段判定"。
> 建议统一走一个 `InputBus`：`InputBus.on(stage, handler)` / `InputBus.off(stage)`。

> **坑 5 · `precision()` 是同步回调**
> `bar.onclick` + `keydown` 双入口，且没有"移除 keydown 监听"（当前实现靠 `done` 标志位兜底，能跑但会攒监听器）。
> 抽公共 `judgeBar()` 时必须补 `removeEventListener`，否则一局战斗打 10 回合会攒 20 个监听器。

## 七、数值与调平

### 7.1 现有曲线推算（为什么必须有 12 回合兜底）

当前最优解「抱架 → 读招 → 低扫」循环，每 2 回合造成 16 伤害（低扫 2 AP 后 AP 归零触发 `endTurn`）：

```
对手 74 血 / 每 2 回合 16 伤 ≈ 10 回合
自己每 2 回合吃 0~22 伤（读招后重拳 15×0.75≈11），70+ 血可能撑不到 10 回合
→ 双方都在"刚好打不完"的边界上，所以才需要 turn>12 兜底
```

**2.0 的调平目标**：正常打法 **6–9 回合**结束，兜底规则降级为"平局判定"（双方 <20% 血）。

### 7.2 可调参数一览（策划改这一张表就够）

| 参数 | 建议初值 | 作用 |
|---|---|---|
| `FIGHT2_TUNE.AP` | 4 | 每回合行动力（**一局长度几乎由它决定**，改前先跑 play.js） |
| `PLAYER_HP_BASE` | 70 | 基础生命（+ `phy*1.6`，实机 phy18 → 99） |
| `FOE_HP` | 320 | 对手生命（节点 `inter.hp`，`brawl2`） |
| `STAM_REGEN` / `FOE_REGEN` | 0.12 / 0.22 | 每回合体干恢复（对手回得快一点，否则它根本出不了手） |
| `STAM_ON_HIT` | 0.22 | 命中推掉对手多少体干 |
| `STAM_ON_DODGE` / `STAM_ON_TAKE` | 0.14 / 0.30 | 闪避 / 硬吃 自耗体干 |
| `STUN_TAKEN_MULT` | 2.5 | 硬直期受伤倍率 |
| `PERFECT_MULT / GOOD_MULT / MISS_MULT` | 1.9 / 1.3 / 0.7 | 三档判定倍率（与反击 ×2.2 **叠乘**） |

## 九、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 手操维度过多，玩家学不会 | 高 | 分档解锁：第一场战斗只有 `jab / guard / defend`，随剧情逐场加机制；**每场只教一个新东西** |

### 11.2 实施中揪出的 3 个真缺陷

**① `hitFoe` 里 `cb&&cb()` 漏传 `grade`** —— 这是本轮最有价值的发现。

```js
// 错：回调收到 undefined
if(foeHp<=0) return finish(true); cb&&cb();
// 对：
if(foeHp<=0) return finish(true); cb&&cb(grade);
```

`act("combo")` 的回调靠 `g==="miss"` 判断"一段打空就不接连打"，收到 `undefined` 后这个判断
**从来没生效过** —— 空挥也会照样弹连打条。是最小复现确认的：
`vm.runInNewContext("function o(cb){const a=(m,g)=>{cb&&cb();}; a(1.3,'miss');} o(g=>TRACE.push(g))")` → `undefined`。

> 教训：`cb&&cb()` 这种简写在只有一个回调、且回调不关心参数时看不出问题；
> 一旦回调开始读参数，它就成了静默的错误源。回归闸就是 §6.1 的「一段偏出 → 不接连打」。

**② 音效播放把判定结果吞了** —— 玩法正确性不能绑在音频层上。

`precision()` 里原本是"播完音效紧接着 `cb(grade)`"。当 `new Audio(不存在的文件).play()` **抛异常**时
（`_playMedia` 里有 `catch` 但 `precision` 里没有），`cb(grade)` 永远执行不到：
玩家点了判定条、条也消失了，但这一招**完全没结算**，看起来就是"卡住了"。
现在音效单独 `try` 包裹，注释写明"音频层出问题绝不能影响判定"。

**③ 组合拳一段的伤害延迟 4 秒才显示** —— `hitFoe` 现在显式 `renderFight()`。
原设计里伤害日志要等 `after()`，而组合拳的 `after()` 在连打结束之后才跑
（中间是连打覆盖层），玩家会以为"刚才那下没打中"。

浏览器层跑不起来（本机 Chrome 无头受限、mshta 不稳），所以这三套都是**把真实代码抽出来驱动**，

| `fight-loop` | `startFight` 整个函数 | 假 DOM + 假时钟 + **排队式 rAF**（逐帧放行，把光标真实推到目标档位） |

### 13.2 P2 又揪出 2 个真缺陷

**① 硬直标志设得太晚，那一击吃不到 ×2.5。**

`applyFoeDamage` 原本是"先算伤害 → 再扣体干 → 最后置 stunMine"。

`whiffOpenCounter()` 里也置 `foeStun`，而 `foeTurn()` 的 rest 分支已经表达过"打不出来"了，

### 13.3 手感设计上的两个刻意选择

1. **对手招式库是确定性轮转，不是随机抽招。** 随机抽会让"读招"失去意义
   （读到了也来不及反应），轮转配合 450ms 红闪才是可学习的节奏。
   等 P4 加权重状态机时，"学乖/急眼"这类**有理由的**偏离才会出现。
2. **防守只看方向、不看位置。** 防守阶段的判定条被复用成"红闪计时条"，
   所以隐藏了完美区、`zones` 传空数组 —— 玩家在这一阶段只需要按对方向。

### 13.4 调平（已修）—— 从 2 回合到 6–9 回合

**问题**：P2 第一版实测 **2 回合**就打完（对手 74 血，一回合 3 拳 ≈ 69 点）。
一局 2 回合的格斗，体干/硬直/反击窗口**一次都来不及触发**，等于白做。

**为什么手算会错**：战斗里有体干恢复、硬直跳回合、对手喘气、反击叠乘、格挡抵消
互相影响，手算偏差极大。所以这次是**实测标定**：把"回合数"做成测试里的断言，
改一次数值跑一次测试。

**改了什么**

| 项 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 每回合行动力 | 3 | **4** | 招式统一 2AP ⇒ 每回合 2 次有效攻击（3AP 只能出 1 次，节奏太钝） |
| 直拳消耗 | 1 AP | **2 AP** | 与其它招统一；1AP 直拳是最优解 ⇒ 3 拳/回合 ⇒ DPR 69 |
| 对手血量 | 74 | **320** | 配 DPR ≈ 46 正好 6–9 回合 |
| 对手伤害 | 9/6/15/11 | **30/18/45/34** | 对手一局只有约 5 次出手（受体干限制），单次必须够疼 |
| 对手体干恢复 | 0.06 | **0.22** | 0.06 时对手几乎全程在喘气 ⇒ 玩家永远不挨打 ⇒ 防守失去意义 |
| 闪避自耗体干 | 0.08 | **0.14** | "一直闪"不该是免费的 |
| 低扫 | 16 | **17** | 与 2AP 档的其它招拉开一点差异 |

**实测结果**（`node tools/dev/play.js`）

| 打法 | 回合 | 剩余血 | 硬直 |
|---|---|---|---|
| 完美判定 + 每次闪对 | **6** | 99/99 | 0 |
| 只打良好档 | **8** | 99/99 | 0 |
| 完美判定 + 从不闪 | **8** | 33/99 | 1 |

也就是说：**手好 = 又快又零伤；手不好 = 拖长且掉 2/3 血**。"从不防守"不再是免费的了。

**防漂移**：`tests/fight2.test.cjs` 里新增了一组调平断言 ——
"理想打法一局落在 6–9 回合"、"从不防守的代价明显更大"、"一局内至少触发一次对手喘气"。
数值再漂回 2 回合，测试立刻红。

**调平工具**：`node tools/dev/play.js [perfect|good|nosdodge]` —— 用真实 `startFight2`
打完整局并逐回合打印（出招伤害、防守结果、体干、回合数）。改数值后先跑它。

### 13.5 调平中揪出的 1 个真缺陷

**对手出"抱架/虚招"时，回合会永远卡死。**

这两招不需要玩家闪，所以我当初开的判定条**没传 `keys`** ——
而 `judgeBar` 的逻辑是"有 keys 时收方向键、没 keys 时收空格"，
两样都没给 ⇒ **这条判定条没有任何输入途径**，只剩 `duration` 超时一条路。
真人在浏览器里 rAF 会自然推进、超时能兜住；但任何"手动驱动 rAF"的场合
（自动化测试、以及调平工具）都会**永远卡在防守阶段**。
实测：对手第一次出"抱架"就把整局打死在那里，一眼看去像"回合不推进"的玄学 bug。

修法：不用闪的招**同样传 `keys`** —— 按任意方向都能过去（这一手本来就不看方向，按什么都不会受伤）。

## 十四、P3 侧视舞台实施记录

### 14.1 为什么先做"程序化剪影"、后来又换成 Lovart 立绘

用户提出"视觉上不好看、想要拳皇那种视角"。先做了素材审计，结论改变了第一版方案：

| 素材 | 实际情况 | 能不能用于侧视对战 |
|---|---|---|
| 打斗实拍 `box_glove` / `box_ring` / `box_ko` | 3 段共 200 秒、1280×720，但都是**综艺教学片机位**：中近景、正对镜头 | ❌ 抽帧拿不到可用的全身侧视姿态（已实抽多帧确认） |
| `art/` 目录 | 只有 15 张头像、3 张场景图、若干图标 | ❌ 没有任何角色立绘或动作帧 |
| `map3d.js` | Three.js r149 + **程序化 canvas 贴图**（地面/墙/屋顶都是代码画的） | ✅ 项目已有"代码画素材"的路线 |

所以第一版做**代码画人**：canvas 侧视对战舞台，风格定为**霓虹夜景剪影 + 轮廓光**。

随后用户追加了明确要求：**"不一定要截取真人全身图，用 Lovart 抓取人物特征做类似拳皇的小人，
点开始战斗之后化身进入拳皇游戏机里开始打斗"**。于是：

- 用 Lovart 以真人参考图生成**两套四姿势立绘**（见 14.6），程序化剪影**降级为立绘未就绪时的回落路径**；
- 加一段"**化身进街机**"的开场过场（见 14.7）。

> ⚠ 回落路径不是废码：无头测试环境没有真 `Image`，永远走回落；立绘加载慢时也靠它兜住。
> 两条路都必须能跑 —— 这是 14.6 里那个真 bug 能被抓到的前提。

### 14.2 这一层做了什么（`Fight2Stage`）

| 部件 | 做法 |
|---|---|
| 舞台 | 1680×900 逻辑坐标；天幕渐变 + 5 块霓虹光斑 + **透视地面网格**（竖线向灭点收、横线按距离加密）+ 地平线高光 |
| 拳手 | 骨架式参数化剪影：头/颈/躯干/肩/大小臂/大小腿/脚/拳套；`main` 色 + `edge` 轮廓光；**脚下阴影 + 地面倒影** |
| 体型 | `BODIES` 按角色分开：身高 `hi` / 躯干 `torso` / 四肢 `arm`·`leg` / 站距 `spread` / 头身比 `head` / 肩宽 `shoulder` |
| 配色 | `PALETTE` 按角色分开（莽夫暖红系 / 陈默冷蓝系），每个角色内部再分**远侧 / 本体**两档明度，都保留轮廓光 |
| 姿势 | `POSES` 按角色分开（idle / strike / hit / stun / ko × **2 套**）驱动 7 个姿势参数，逐帧**插值**过渡，不是硬切 |
| 相机 | 跟随双方中点 + 自动推近（反击窗口 1.14 / KO 1.25）+ **震动**（命中时随机偏移） |
| 演出 | 命中 → 放射火花 + 扩散环 + 顿帧（hitstop）+ 闪白；偏出 → 无火花；KO → 横幅 + 输家倒地 |
| HUD | 画在 canvas 上：双方血条（从中间往外掉）+ 体干细条 + `R回合数` + 行动力点 + 状态徽记 |
| 待机 | 呼吸起伏（`bob`），没人操作时画面不是死的 |

**两个角色怎么做到"一眼能分辨"**（三件叠加，缺一件就退回"同一个人换色"）：

| 维度 | 莽夫「花衬衫」 | 陈默 |
|---|---|---|
| 体型 | 矮壮：`hi 0.90`、躯干 `0.34`、四肢 `0.150/0.158`、站距 `0.20`、肩宽 `0.175` | 高瘦：`hi 1.06`、躯干 `0.27`、四肢 `0.122/0.130`、站距 `0.14`、肩窄 `0.132` |
| 动作 | 大开大合：出拳 `lean 0.26 / step 0.85`、倒地 `crouch 0.84` | 紧凑收敛：出拳 `lean 0.16 / step 0.42`、倒地 `crouch 0.70` |
| 配色 | 暖红系：本体 `#3a1620`、轮廓光 `#ff4d6d`、拳套收口 `#ff6b52` | 冷蓝系：本体 `#1b2133`、轮廓光 `#4dd8ff`、拳套收口 `#7fe6ff` |

> 幅度差定成 **≥1.5 倍**（出拳 lean 0.16→0.26、step 0.42→0.85）并写成了断言 ——
> 差得太少玩家读不出风格差异，这条约束容易被后续调参悄悄磨平。
>
> ⚠ **配色只作用于骨骼回落路径**：立绘就绪时走立绘分支，`PALETTE` 不参与绘制。
> 所以"暖红 vs 冷蓝"在常规样片里看不到 —— 要验它必须强制摘掉立绘，
> 见 `node tools/dev/palette-check.js`（输出 `palette-check.png`）。

**与机制的接线**：`hitFoe` → `hit()`；`resolveFoeMove` → 闪避/格挡/挨打三种演出；
`finish` → KO 横幅 + 倒地；每次 `render()` 把状态 `sync()` 进舞台。
机制一行没改 —— 加这一层时只有 1 条旧断言（断言已删除的 DOM 血条）需要改写成"状态已同步"。

### 14.3 免浏览器看效果：`tools/dev/stage-preview.js`

把**真实的 Fight2Stage** 抽出来，喂一个"最小 canvas 实现"（`tools/dev/canvas-sink.cjs`），
逐帧编码成 `stage-preview.mp4`。立绘也是真的：`art/fight2/*.png` 由 `png-read.cjs` 解码后
喂进 `drawImage`（预览里的 `Image` 桩是同步 `onload` 的）。
定位是**近似预览**：构图/站位/配色/镜头/节奏/立绘为真，渐变与文字做了简化。
最终验收还是要在浏览器里（标题屏「⚑ 跳到打斗 2.0」）。

```
node tools/dev/stage-preview.js                 # 完美打法一局（含街机过场）
node tools/dev/stage-preview.js nosdodge        # 从不闪，看挨打演出
node tools/dev/stage-preview.js perfect nointro # 跳过过场
node tools/dev/sprite-sheet.js                  # 立绘对照图（带回归闸）
```

写这个工具时踩的坑值得记（都是"渲染出来一片错"的典型）：

1. **`fillStyle` 可能是渐变对象而不是字符串** —— 只处理字符串的话会回落成白色，
   整个天幕被刷成纯白（样片第一版就是一张白纸）；
2. **粗线段要沿法线方向铺宽度** —— 只按 y 偏移画的话，20px 粗的手臂会退化成 2px 细线，
   人物"只剩一个头圈、身体整条消失"（样片第二版）；
3. **`drawImage` 要支持 translate+scale（含镜像）的完整仿射** —— 倒影是 `scale(1,-0.42)` 画的，
   只按缩放算会把倒影画到天上；采样用**前向映射**（逐源像素打到目标），缩小时不会漏采样。

### 14.4 比例与观感的三次修正

| 版本 | 样片看到的问题 | 改法 |
|---|---|---|
| v1 | 画面一片白 | 修预览器的渐变处理（见 14.3-①） |
| v2 | 人物只剩头圈 | 修预览器的粗线描边（见 14.3-②） |
| v3 | 人形**太瘦太长**，像竹竿 | 身高 300→420、躯干 0.20→0.30 宽、四肢 0.085→0.125~0.155、加肩球与颈 |
| v4 | 脚下阴影成了两个**黑饼** | 阴影 0.52×0.075/0.34 → 0.30×0.034/0.20 |

> 教训：预览工具也会骗人 —— 分不清"是工具画错了还是设计不对"时，
> 先用最小的改动同时验证两边（比如临时把背景换成纯色看人物轮廓）。

### 14.5 已知边界

- **不是像素级还原**：预览是近似的，浏览器里更好看；但也别指望它等于 KOF 的角色美术
- **立绘只有 4 个姿势**（idle / strike / hit / ko）；机制里用到的 `stun` 没有对应立绘，
  会**回落成骨骼剪影** —— 所以你会偶尔看到同一个人在两套画风之间切换。这是已知取舍
  （省钱：一套 4 姿势双人图 ≈ 2 张 1024×1024 生成图）
- **没有左右移动**：站位固定，只有出招/受击/倒地位移（距离轴仍未做）
- 背景是程序化霓虹，没有与剧情的场景绑定（后巷/拳馆还没区分）
- 立绘脚底与地面线有 **0~20px** 的残差：源图里"最低不透明像素"其实是各姿势不同的
  接地阴影/拳套，不是脚。已经做到"肉眼看不出跳脚"（第一版是 183px 的跳脚）

### 14.6 Lovart 立绘链路（生成 → 切图 → 绘制 → 核对）

**① 生成**（`tools/dev/_p_sprites.json` + `tools/dev/lovart_gen.py`）

两张 1024×1024 绿幕图，每张横排四格（待机/出拳/受击/倒地）：

| 角色 | 游戏内身份 | 参考 | 造型 |
|---|---|---|---|
| `puncher` | 玩家「陈默」 | `_ref/ref_leijie.png` | 瘦高、短发、白拳套、运动短裤，蓝 `#4dd8ff` 轮廓 |
| `brawler` | 对手「花衬衫」 | — | 矮壮、花衬衫、工装裤，红 `#ff4d6d` 轮廓 |

风格写的是"90 年代街机 2D 格斗手感 + 三头身"，**不使用任何 KOF 商标/角色**。

> 驱动方式：`lovart_gen.py`（Python 读 JSON → subprocess 调 `agent_skill.py chat --json --download`）。
> 为什么不直接敲 PowerShell：`--prefer-models '{"IMAGE":[...]}'` 里的 JSON 会被 PowerShell 的
> 引号处理搞坏，实测生成出一堆无关图。

**② 切图**（`tools/dev/cut-fight2-sprites.ps1`）

色度抠像（`G > 90 且 G > R×1.35 且 G > B×1.35`）→ 按列切 4 格 → 裁到不透明边界 →
**把四格的落地点平移到同一条地面线** → 输出透明 PNG + `<slug>.json` 索引。

索引里每个姿势记 `{file, w, h, lowY}`；`lowY` = 该图**不透明最低行**。
`standH` 用站姿那张的高度（`puncher` 309 / `brawler` 423）。

**③ 绘制**（`index.html` 的 `Fight2Stage.drawFighter` 立绘分支）

| 事实 | 做法 | 不这么做会怎样 |
|---|---|---|
| 四张图高度差极大（309 vs 126） | 缩放基准取**站姿高度** `standH`：`k = 420×body.hi / standH` | 按各图自身拉高 → 倒地那张被放大 3.3 倍，宽 780px |
| 切图对齐后底部留 0~21px 空档 | 用 `lowY` 当贴地锚点（不是图片底边） | 人陷进地里 |
| 对手要镜像 | `scale(-1,1)` **绕贴地点**镜像，图也从 `-dw/2` 画 | 图被甩到锚点另一侧（花衬衫立绘紧贴格子右缘、一半出画） |
| 立绘 slug 与体型档位不是一回事 | 查表用 `f.sprite`（`puncher`），**不是** `f.who`（`player`） | 见下面的真 bug |

**④ 核对**（`tools/dev/sprite-sheet.js`）

用**真实的 `drawFighter`** 把四姿势各画一格导出 PNG 对照图（左半立绘 / 右半骨骼回落），
并在终端打出"脚底-地面线""立绘身高""倒地宽度"，超标就非 0 退出（可当回归闸）。
配套：`tools/dev/png-read.cjs`（自己写的 PNG 解码，只依赖 Node 内置 zlib）、
`png-write.cjs`（写 PNG）、`canvas-sink.cjs`（带 `drawImage` 的最小 canvas）。

> 对照图里倒地姿势右边被切掉一截，是**预览窗口的限制**（半格只有 210px 宽，躺下的人比这宽），
> 不是游戏里被裁剪 —— 实拍样片 `stage-preview.mp4` 里的倒地是完整的。

### 14.7 "化身进街机"过场

点「开始战斗」后 1.6 秒的过场：街机机身升起 → 屏幕通电发亮 → 镜头推进屏幕 → 淡出到黑 → 开打。
实现是 `Fight2Stage` 里的 `arcade` 进度（`startArcade()` / `drawArcade()`）+ `startFight2` 里的
`transitionGuard()`（过场期间出招会被挡，并提示"你正被吸进那台街机 —— 稍等"）。

### 14.8 这一轮揪出的 3 个真缺陷（都不是"看画面"能发现的）

**① `drawFighter` 用 `f.who` 查立绘 → 陈默永远走骨骼回落**

`f.who` 是**体型档位**（`"player"` / `"brawler"`），立绘 slug 在 `f.sprite`（`"puncher"` / `"brawler"`）。
`SPRITES.player` 不存在 → `spriteOf()` 返回 `null` → 玩家那一侧永远回落骨骼。
花衬衫只是**恰好** `who` 与 `sprite` 同名（都是 `"brawler"`），所以一半角色是对的。

> 为什么难发现：无头测试环境没有真 `Image`，立绘分支**零覆盖**；而看画面时"蓝色剪影"
> 与"蓝色立绘"在小尺寸下极像（实拍样片里我一直以为两个角色都在用立绘）。
> 最终是用**A/B 像素比对**定性的：同一帧"装立绘"与"强制摘掉立绘"渲染出的字节**完全相同（0.0%）**
> —— 这才证明立绘分支根本没执行。
> 现在 `tests/fight2.test.cjs` 里有一组专门的立绘几何断言（装了假立绘 + 记账桩 canvas），
> 断言"落地点按 lowY 贴地""以贴地点为中心""倒地不放大"。

**② 切图脚本的 `ground` 参数其实没生效**

脚本算了统一地面线 `$ground`，但把每格内容重绘进新画布时**没有按 `ground` 平移 y**
（`dstRect` 的 y 恒为 `padTop`）—— 等于"各格各自对齐"。后果是各姿势脚底差 4~21px：
出招/受击时人会浮起或陷进地里。修法是加一次平移 `padTop + (ground - maxY)`，
并把得到的落地点写进索引的 `lowY`。

**③ 预览工具与量测工具自己会骗人（三次误报）**

| 误报 | 真相 |
|---|---|
| "命中没有特效"（`fx=0`） | 我推了 30 帧，而顿帧 12 帧 + 火花寿命 14~24 帧 —— **特效已经演完了**（`fxCount=1` 证明生成过） |
| "花衬衫低于地面 182px" | 量到了**地面倒影**（`globalAlpha 0.18` 画的）。要用"被 ≥50% 不透明度写过的像素"来量 |
| "骨骼身高只有 30px" | 判"内容"时顺手把地面线的颜色也排掉了，结果骨骼的蓝边 `rgb(62,157,190)` 一起被吃掉 |

**教训**：这一层里"看到的"和"以为看到的"差别太大。所以核对工具本身要能被质疑 ——
量测口径写进注释（为什么用 80 分位、为什么要排掉倒影），断言要能区分**性质错误**与**取整误差**。
