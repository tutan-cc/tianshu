| 类别 | 实测 |
| --- | --- |

## 7. 我发现的问题 / 与需求原文的差异 / 诚实局限

### 7.1 ⚠ 客户端 8 s 超时对 jev 的尾部延迟偏紧（**待决定，未改**）

写入方扩写的 `tools/dev/nlroute-browser.js` 里那条真接口用例，我跑的时候出现：
`intent=none conf=0 err="timeout>8000ms" latencyMs=8007`（输入「手痒了，想上桌搓一把」），
即 **`nlroute.js` 的 `TIMEOUT_MS=8000` 被真实上游延迟打穿**。而我在同一台机器上的 9 次真请求是 401–1011 ms。

- 影响：偶发一条 `timeout>8000ms` 的 error 记录（不跳转、不影响游戏，但语料里会多一条噪声，玩家看到「解析失败」）。
- 建议（未实施）：把 `TIMEOUT_MS` 提到 12–15 s，或做成可配；影子模式本身是异步的，多等几秒不阻塞游戏。
- 这条**不是**我发现的实现 bug，而是**我独立观测到的延迟尾部风险**，供上级决定。

### 7.2 与需求原文的差异（我认为可接受，按事实记录）

1. 上游超时 → 实现用 **504**（原文写 502）；页面已映射成中文。
2. `available()` 在"反代中途被杀、且尚未重新探测"的瞬间仍是 `true`（缓存语义）。第一次提交会写一条 error 记录 +
   点名文案，之后 health 被置不可用、后续走 `no-endpoint`。**需求给的两条降级路径是"或"关系，两条都成立**。
3. `GET /health` 会向本机来源暴露 `hasKey` 布尔值（不含凭据本身）；这是"让页面知道反代在不在"的必要信息。

### 7.3 安全边界（达成 + 残余风险）

**达成**：key 只在 Node 侧（只从环境变量/Windows 用户级变量读，不落盘、不打印、不进浏览器，实测 `/health`、转发响应、
503 体、反代日志**四处逐字比对均无 key**）；`Authorization` 来自浏览器的会被丢弃；Origin 白名单在 **OPTIONS 与 POST 两层**校验，
非白名单 **403 且不转发**；只监听 `127.0.0.1`（不是 0.0.0.0）。

**残余风险（如实列出）**：

1. **`null`（file://）来源被放行**：本机任何 `file://` 页面都能调用反代（同机同用户，风险≈本机脚本）。
   要收紧：`node tools/dev/nlroute-proxy.js --no-null-origin`（我验过：null 的 POST 与预检都变 403）。
2. **反代不做调用方认证**：只要能访问 `127.0.0.1:8010`（同机其它用户/进程），就能用它打模型、消耗额度。
   当前只靠"本机 + Origin 白名单"兜。要更严可加一次性 token（未做）。
3. **端点可被持久化**：`nlroute.js` 把端点写在 `localStorage['cs2_nl_endpoint']`；被改到恶意端点会把请求发过去
   （但 key 不在浏览器，损失有限）。
4. 明文 HTTP：仅本机回环，且不含凭据，可接受。

### 7.4 其它局限

1. **真实玩家语料仍为 0**：本报告 10 条是我写的测试输入。
2. 只在 **Windows + Chrome headless** 上验过；Firefox/Safari 未验（`null` Origin 行为、预检头兼容未测）。
3. 我验收期间 `index.html` 被**另一个并发 agent** 改过（10:45:32，299750 → 316904 B，内联脚本变长）。
   我以三道闸门确认页面仍可用：`check-inline.js` 两段内联脚本语法 OK、`nlroute.js` 仍被加载（第 660 行）、
   真浏览器端到端 95/95。**但我没有审计它改了什么**（不属于本任务），也不对此负责。
4. 我按需使用 `NLRoute.debug.setEndpoint` 等新 API，未穷举其非法输入边界（例如把端点设成奇怪字符串）。
5. 单条用例只跑了一遍（真接口概率有抖动）；第 1 条的 989 ms 含冷启动。
