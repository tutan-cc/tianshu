## 1. 架构：为什么必须走本地反代

```
┌──────────────────────────┐        ┌───────────────────────────┐        ┌──────────────────────────┐
│  游戏页面（浏览器）        │  POST  │  本地反代 nlroute-proxy.js │  POST  │  TypeSafe System One     │
│  index.html + nlroute.js  │ ─────▶ │  127.0.0.1:8010 /route     │ ─────▶ │  api.typesafe.ai/v1/...  │
│                          │        │                           │        │                          │
│  ✗ 没有任何 key           │        │  ✓ key 只在这里（环境变量）  │        │                          │
│  ✓ 只读 localStorage 语料 │        │  ✓ 补 Authorization        │        │                          │
│  ✓ 只改一行提示文字        │        │  ✓ 来源白名单 + CORS 头     │        │                          │
└──────────────────────────┘        └───────────────────────────┘        └──────────────────────────┘
      GET /health 探活 ────────────────┘   （页面靠它判断"端点可用"，**不需要 key**）
```

**为什么不用直连**（实测，不是偏好）：TypeSafe 的 CORS 预检只放行白名单 Origin ——

```
OPTIONS (Origin: null)                  → 400  body: "Disallowed CORS origin"
OPTIONS (Origin: http://127.0.0.1:8000) → 400  body: "Disallowed CORS origin"
真浏览器（默认 Web 安全模型、页面在 http://127.0.0.1:8000）：
Access to fetch at 'https://api.typesafe.ai/v1/systemone' from origin 'http://127.0.0.1:8000'
has been blocked by CORS policy: Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.
```

带着 `Authorization` + `application/json` 的 POST **必然触发预检**，预检不过请求就到不了模型。
反代一次解决两件事：① 页面只跟 127.0.0.1 说话，跨域判断不再发生；② **key 不必进浏览器**。

### 三条命令（或一条）

```powershell
# ① 设一次 key（新终端生效；不写进任何文件）
setx TYPESAFE_API_KEY "apikey_..."

# ② 一键起「反代 + 静态服务」，并打印下一步
powershell -NoProfile -ExecutionPolicy Bypass -File tools/dev/nlroute-up.ps1
#    → ✔ 反代在跑：http://127.0.0.1:8010   ✔ 静态服务在跑：http://127.0.0.1:8000/index.html

# ③ 收摊
powershell -NoProfile -ExecutionPolicy Bypass -File tools/dev/nlroute-up.ps1 -Stop
```

不想用脚本也行（等价的手工三条）：

```powershell
node tools/dev/nlroute-proxy.js            # 终端 A：反代 127.0.0.1:8010
python -m http.server 8000                 # 终端 B：静态服务
# 浏览器打开 http://127.0.0.1:8000/index.html
```

> `nlroute-up.ps1` 实测：1.2 秒内起齐两个服务、`/health` 与 `/index.html` 都是 200、`-Stop` 用 `taskkill /T` 把两棵进程树都收干净（端口随即释放）。
> 它只往 `%TEMP%\nlroute-up\` 写日志与 PID 记录，**不改仓库任何文件**。

## 2. 模块 API（`nlroute.js`，自包含 IIFE）

| API | 说明 |
| --- | --- |
| `NLRoute.available()` | 端点可用？**反代模式**= `/health` 探通（**不需要 key**）；**直连模式**= 配了 key |
| `NLRoute.configure(x)` | `x = "apikey_…"` 或 `{key, endpoint}`；只写浏览器 `localStorage`，本模块不含任何凭据 |
| `NLRoute.setEndpoint(url)` / `endpoint()` | 切端点（传空 = 回到默认反代 `http://127.0.0.1:8010/route`）；切完自动探一次 |
| `NLRoute.probe()` | `→ Promise<boolean>`，立刻 `GET <origin>/health` 探一次；永不 reject |
| `NLRoute.route(text)` | `→ Promise<result>`，**永不 reject**。result：`{intent, confidence, margin, candidates[{id,p,name}], needsConfirm, signals{in_game_action,out_of_bounds,urgency}, reasons[], skipped, latencyMs, cached, error, raw, model, usage}` |
| `NLRoute.log()` / `clear()` | 读 / 清语料记录（`localStorage['cs2_nl_log']`，上限 200） |
| `NLRoute.exportJSON([{download}])` / `download()` | 导出语料（每条含真实去向 `actual` + 对账统计）/ 直接下载 `nl-corpus.json` |
| `NLRoute.backfill(id, why)` | 把最近一条未回填记录的 `actual` 写成 id |
| `NLRoute.debug.*` | `setFetch`（注入假 fetch）· `setEndpoint` · `probe` · `health` · `stats` · `last` · `hooks` · `ui` · `rules` · `games` · `markActual` · `pushRecord` · `submit` |

请求形状（与原型逐字一致，措辞是**实测标定**出来的）：

```
POST <endpoint>            # 默认本地反代 /route；可切回 https://api.typesafe.ai/v1/systemone
Authorization: Bearer <key>   ← **只有直连才带**；走反代时这个头根本不出现
Content-Type: application/json
body = { state:{ player_utterance, minigames{10 项目录}, common_phrasings{口语对照} },
         model:"jev-latest",
         questions:{ intent:{choice, criteria: map<option,描述>（含 none）},
                     in_game_action:{noul, criteria{true,false}}   ← 正反边界写清
                     out_of_bounds:{noul, criteria{true,false}}    ← 独立兜底
                     urgency:{score, criteria:[4 档有序]} } }
```

## 3. 判定口径与加固规则（硬性约束，未改动；只有超时**默认值**在 v1.2 放宽）

```js
OOB_MIN: 0.35   CONF_MIN: 0.5   MARGIN_MIN: 0.2   MIN_CHARS: 2
TIMEOUT_MS: 15000（默认，**可配 1~60s**；v1.1 是 8000）   CACHE_MS: 30000   BACKFILL_MS: 60000   LOG_MAX: 200
HEALTH_TIMEOUT_MS: 1500   PROBE_THROTTLE_MS: 3000
```

| # | 条件 | 结果 | 依据 |
| --- | --- | --- | --- |
| ① | 去空白后 < 2 字 或 纯符号 | 直接 `none`，**不发请求**（仍记一条语料 + 原因） | 原型实测：单字「打」被自信路由到 fight(0.79) |
| ② | `out_of_bounds >= 0.35` | `intent = none`，`needsConfirm = false` | 有一条注入样本 `oob=0.49` 在 0.5 阈值下擦边放行 |
| ③ | `confidence < 0.5` 或 `margin < 0.2` | `needsConfirm = true` | `confidence.md` 三档策略 |
| ④ | `intent === 'none'`（非越界） | `needsConfirm = true`（走追问分支） | 照原型 |
| ⑤ | 相同输入 30s 内 | 内存缓存（不落盘），不再打接口，但仍记一条语料 | 防手快连点，又掩盖不了抖动 |
| ⑥ | 请求超过预算（默认 15s） | `intent:"none"` + `errorKind:"timeout"` + error 记录；**不动 health**（端点可能只是慢） | 见下面的"超时为什么是 15s" |

**超时为什么从 8s 提到 15s（v1.2）**：验收方在同机实测 9 次真请求 **401–1011ms**，但偶发一次打穿 8s
（记录到 `latencyMs=8007 / err="timeout>8000ms"`）→ 语料里混进一条噪声、玩家看到一次"解析失败"。
影子里"多等几秒"的代价只是那行小字晚一点更新（**绝不跳转、不挡游戏**），而"把偶发慢当成失败"会污染语料。
热路径中位 ≈480ms，15s ≈ 中位的 30 倍、也比观测到的毛刺宽一倍。

**可配方式**（三个入口，落 `localStorage['cs2_nl_timeout']`，一律夹到 1~60s）：

```js
NLRoute.setTimeoutMs(20000)            // → 20000（生效值）
NLRoute.configure({ timeoutMs: 9000 }) // 一起配也行
NLRoute.debug.setTimeoutMs(0)          // 传 0/非法 → 恢复默认 15000
NLRoute.timeoutMs()  NLRoute.debug.rules().TIMEOUT_MS  NLRoute.debug.stats().timeoutMs   // 读生效值
```

**两类失败必须分得开（v1.2）**：记录里新增 `errorKind` / `errorStatus`，`errorKind ∈`

| errorKind | 含义 | 触发 | UI 文案 |
| --- | --- | --- | --- |
| `timeout` | **等满了我们自己的预算**（端点可能只是慢） | 客户端定时器先到 | 「解析超时（等了 15s 没回来）—— 上游可能慢，或反代卡住了；可 `NLRoute.debug.setTimeoutMs(30000)` 放宽」 |
| `unreachable` | **请求根本没到端点** | fetch reject / 无 fetch（`Failed to fetch`） | 「连不上端点 —— 本地反代没在跑？执行 node tools/dev/nlroute-proxy.js」 |
| `http` | 端点答了，但状态码非 200 | 401/403/429/502/503/504（`errorStatus` 记下具体码） | 按码给处置建议（401 key 无效 / 403 白名单 / 502·504 上游超时或不可用 / 503 反代没拿到 key） |
| `bad-response` | 答了但读不懂 | 缺 `answers` / JSON 解析失败 | 「响应读不懂（…）—— 多半是网关/代理返回了非 JSON」 |

这样语料里能直接按类统计"偶发慢"与"根本没连上"，而不是混在一个 `error` 字符串里。
`stats` 同步新增 `timeouts` 与 `lastErrorKind`。

**失败静默**：超时 / 非 200 / JSON 坏 / 缺 `answers` / 网络层失败 → `intent:"none"` + `error`(+`errorKind`) + 写一条 `error` 记录，**从不抛给调用方**；
端点不可用时 `route()` 连 POST 都不发（`skipped: "no-endpoint"` / `"no-key"`），也**不写记录**。

## 4. 影子模式 UI 位置与行为

- **位置**：主界面**侧栏 `#side`**，紧挨「🀄 找人打两圈」「🍳 做份早餐」（`#bfBtn` 的下一个兄弟、`#bfNote` 的上一个兄弟）。
- **构建方式**：`nlroute.js` 动态插入 `#nlShadow` —— 所以 `index.html` 只加了一行 `<script src>`。
- **可见性规则**（v1.1 第 2 版，见 §8 的口径变更）：`available() || hasKey() || 反代模式`。
  即**默认（反代）模式下永远可见** —— 全新玩家（反代没起、也没配 key）也得看得见
  「先执行 `node tools/dev/nlroute-proxy.js`」这句指引；**显示本身不发任何请求**。
- **无声**：不碰 `AudioSys`。
- **提交后唯一的副作用**：输入框下方那行小字。三种典型文案：

```
🧠 影子模式 · 识别为「麻将 · 听牌挑战」100% · 未跳转（本功能仅记录）
🧠 影子模式 · 没对上任何玩法（以上都不是 51% / 股市 · 六个交易日 30%） · 未跳转（本功能仅记录）
🧠 影子模式已开启，但本地反代没在跑 —— 先执行 node tools/dev/nlroute-proxy.js（本功能仅记录）
⚠ 解析失败（已静默回落）· 连不上端点 —— 本地反代没在跑？执行 node tools/dev/nlroute-proxy.js（或网络断了） · 未跳转（本功能仅记录）
⚠ 解析失败（已静默回落）· 上游超时或不可用，稍后再试（反代日志里有详情） · 未跳转（本功能仅记录）
```

- **绝对不跳转**：模块里没有任何 `startXxx()`；浏览器探针放了 7 个哨兵函数并断言调用次数为 0，
  还逐项比对了提交前后的 15 个 overlay 的 `on` 位串 / `isBusy` / `S.done` / 羁绊数值。

## 7. 本地反代的行为契约与安全边界

| 路由 | 行为 |
| --- | --- |
| `GET /health` | 200 `{ok, service, version, upstream, model, hasKey, keySource, keyLen, uptimeMs, stats}`（**只报 key 长度，不报内容**） |
| `POST /route` | 原样转发请求体到上游，补 `Authorization`；**状态码与响应体一字不改地透传**（400/401/422/429 都照传）；透传上游 `x-typesafe-request-id` |
| 其它路径 | 404 结构化错误 |
| 上游挂 / 超时 | 502 `upstream_error` / 504 `upstream_timeout`（结构化错误体，不崩） |
| 没 key | 503 `no_key` + 明确说清要设 `TYPESAFE_API_KEY`，且**不去问上游** |
| 请求体不合法 | 400 `bad_request`（反代不猜字段、不补） |

**安全边界（本节是 v1.1 的重点）**

1. **key 只在 Node 侧**：只从环境变量（Windows 再兜底一次用户级变量）读；浏览器 localStorage 里一个凭据都没有；
   收到的 `Authorization` 头**一律丢弃**（浏览器说它有什么 key 都不算数）。
2. **来源白名单在 OPTIONS 与 POST 两层都校验**（P0 修复，见 §8.1）：
   非本机来源（不是 `http://127.0.0.1:*` / `http://localhost:*` / `null`）**一律 403 且不转发**。
   只校验预检会被"简单请求"绕过（`Content-Type: text/plain` 不触发预检）→ 本机反代就成了公网可用的 LLM 中继。
3. **为什么 `null` 也在白名单里**：游戏可能从 `file://` 直接打开（Origin 就是 `null`）。
   残余风险：恶意页面也能用 sandbox iframe 造出 `Origin: null`。
   要更严就 `node tools/dev/nlroute-proxy.js --no-null-origin`（代价：file:// 打开的游戏用不了，必须从本地 HTTP 起）。
4. **无 `Origin` 头 = 本机工具**（curl / 仓库探针）：浏览器跨源请求一定会带 Origin，所以"没有 Origin"这条路留给了本机工具。
5. **只监听 127.0.0.1**（不是 0.0.0.0），局域网里别的机器连不上。
6. **日志纪律**：只打 方法/路径/请求体**字节数**/耗时/状态码 + 上游 request-id；**不打 key、不打 state**
   （`--verbose` 才额外打一句玩家原话）。单测里有一条断言专门扫日志里有没有 key 的完整串与中段。

## 8. 验收方的 4 条发现：修法与「原→新→原因」（等复验）

> 独立验收方（只读 + 文档）实测出 4 条问题，已全部修掉。下面每条都写清**原来的行为 → 现在的行为 → 为什么**，
> 并给出新增的断言名（都在 `tests/nlroute.test.cjs` 里，可逐条跑）。

### 8.1 【P0 安全】`POST /route` 不校验 Origin → 可被当 LLM 中继

- **原来**：只有 `OPTIONS` 校验来源（非白名单不给 ACAO 头），`POST` 层不校验。
  恶意页面用 `Content-Type: text/plain` 发**简单请求**（不触发预检）即可让本机反代**原样转发并消耗一次调用**。
- **现在**：`POST` 与 `OPTIONS` **都**过同一套 `originDecision()`；非白名单 → **403 `forbidden_origin`**，
  **一个字节都不转发**（`stats.forbidden` 计数）。
- **原因**：反代持有真 key，"能不能被别人的网页调用"是凭据边界问题，不是体验问题。
- **断言**：`非本机 Origin 的 POST → 403（哪怕 Content-Type 是 text/plain 也没用）`、`403 的请求一个字节都没转发给上游`、
  `局域网别的机器来的 Origin 也 403`、`外来源预检直接 403`、`关了 null 之后 file:// 来源也 403`（`--no-null-origin`）。

### 8.2 【P1】反代中途挂掉时，提示没点名"本地反代"

- **原来**：`available()` 用缓存的 health 值（会话中途反代挂掉后仍是 true）→ 不走 `no-endpoint` 分支 →
  玩家只看到「连不上端点（反代没起？或网络断了）」，**拿不到启动命令**。
- **现在**（两条都做了）：
  ① `hintFor` 对网络层失败直接给出
  「连不上端点 —— **本地反代没在跑？执行 `node tools/dev/nlroute-proxy.js`**（或网络断了）」；
  ② `route()` 在 POST **网络层失败**后把 health 置为不可用并**异步重探一次**（3 秒去抖），
  于是 `available()` 如实变 false，下次提交直接走 `no-endpoint` 分支。
  业务失败（401/422/502/504）**不会**误伤可用性 —— 那种情况下端点还活着。
- **原因**：玩家遇到"突然不灵了"时，唯一有用的信息是"去把反代起起来"。
- **断言**：`反代中途挂掉 → health 立刻置为不可用`、`available() 随之变 false`、
  `下一次提交直接走 no-endpoint 分支`、`空转时不再发 POST`、`并异步重探了一次`、
  `网络失败 → 提示点名本地反代`（含 `nlroute-proxy.js` 启动命令）。

### 8.3 【P1】全新玩家看不到任何指引

- **原来**：`#nlShadow` 可见性 = `available() || hasKey()`；两者都假 → 整块 `display:none`，
  那句"先执行 node tools/dev/nlroute-proxy.js"永远不会出现在新玩家眼前。
- **现在**：可见性 = `available() || hasKey() || 反代模式` → **默认（反代）模式下永远可见**，
  并且默认文案按状态给：可用 → 「仅记录判断结果，不会跳转」；不可用 → 「本地反代没在跑 —— 先执行 …」。
  **显示本身不发任何请求**（只有 boot 时那一次本机 `GET /health`）。
- **原因**：影子模式的第一批用户就是开发者/玩家，指引不可见等于功能不存在。
- **断言**：`反代模式下 UI 可见（让新玩家看得见「怎么起反代」）`、`默认提示就是「本地反代没在跑 + 启动命令」`
  （单测 + 真浏览器 `全新玩家：没有 key、端点也不可用 → 但影子块仍然可见`、`仅仅显示指引不会产生任何记录/请求`）。

### 8.4 【P2】502/504 没映射成人话

- **原来**：只映射了 401/503，上游超时（504）与上游不可用（502）会在页面上显示 `HTTP 504` / `HTTP 502`。
- **现在**：502/504 → 「上游超时或不可用，稍后再试（反代日志里有详情）」；顺手补了 403 →
  「反代拒绝了这次请求（403）—— 页面来源不在白名单里」。
- **原因**：`HTTP 5xx` 对玩家与协作者都不是可行动的信息；504 与 502 的处理动作是同一个（等一下再试 / 看反代日志）。
- **断言**：`504 → 「上游超时或不可用，稍后再试」`、`502 → 同一句人话`、`403 → 指向来源白名单`、`502/504/403 的提示也都写明未跳转`。

### 8.5 口径变更清单（原有断言一条没删，只改了 7 条，逐条说明）

5. **目录没按场景裁剪**：每次请求仍带 10 个选项 + 口语对照（≈2,000 输入 token / 次 ≈ $0.000086）。
