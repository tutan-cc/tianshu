## 2. 需求与约束：这套架构是被什么逼出来的

架构选择几乎都能追溯到下面这些约束，评估时应以此为准，而不是拿常规 Web 工程标准去套。

| 约束 | 来源 | 对架构的直接影响 |
|---|---|---|
| **纯静态、双击即玩、无服务器** | `README.md:105` | 不能用 ES module 打包（`file://` 下 CORS 受限）→ 全局脚本 + IIFE；不能有 npm 依赖 |
| **零构建** | `README.md:132` | 没有打包器/压缩/TS/CI 编译；改完刷新即生效 |
| **要兼容 IE11 级引擎**（mshta 降级路径） | `README.md:25`(v1.26) · `小游戏自动化调测指南.md:261-301` | 三个模块统一 **ES5 + 自写 `assign()`**；`tools/bf/trident-probe.js` 专门守这条 |
| **素材授权边界**：实拍视频不入库 | `SOURCES.md:9-12` | 代码必须容忍"没有 `video/`"→ 三级画面兜底；媒体走带外分发 + `link-media.ps1` |
| **素材命名不统一**（`ui-click.mp3` vs `sfx-fight-hit.mp3` vs `amb-alley.mp3`） | `index.html:1004-1013` | 催生**候选路径解析层**（三态 pending/ready/bad），成为全项目音频的必经之路 |
| **改代码的主力是 AI 代理，且改的是 300KB 级单文件** | `tools/dev/patch-literal.js:6-17` | 字面量补丁工具 + 四道闸（唯一性/幂等/备份/语法+回滚）+ 内联脚本语法闸 |
| **曾被浏览器缓存坑过**（CSS 新、`breakfast.js` 旧） | `README.md:164-171` | 常驻版本戳水印 + `stamp.js --check` 作为打包闸门 |
| **沙箱限制**：`node --test` 子进程 EPERM、Chrome 命名管道被拦 | `小游戏自动化调测指南.md:50-51,481` | 测试写成"直接 `node <file>`"；E2E 自带 mshta 降级；浏览器层禁止重定向 stdout（`:118-122`） |
| **一个人 + AI 快速迭代，反复重做素材** | `协作者上手指南.md:19-27` | 自产素材（`audio/` `art/`）入库、第三方素材带外分发；`dist/` 只装产物 |

> 结论：这是一套**为"单人 + AI + 纯静态 + 素材带外"优化的工程**，很多看似"不规范"的地方（全局 IIFE、ES5、脚本而非模块）都是上面约束的解，不是技术债。

## 5. 内核：`index.html` 六层

### 5.1 数据层（659–980）

`NODES` 是唯一内容源，节点 Schema：

```js
nodeId: { loc, name, day, per, ch, mood,
          shots:[{v:"video/x.mp4#t=20", who, t:"台词", bg:"radial-gradient(...)"}],
          inter:{type:"…", …},        // 12 类之一
          after:[…], next:["park"], end:true }
```

效果对象 `r` 由 `applyFx()`（1459）统一解析：`cash/cha/phy/int`、`bond:{id:n}`、`bondAll`、`xp`、`flags[]`、`item`、`bonus:{need:{…}}`。
**设计要点**：玩法只产出"结果档位"（`perfect/ok/miss` 等），效果与数据解耦——所以新增玩法**不用改节点数据、成就、结算卡**（`index.html:2705` 明确写了这条约束）。

### 5.2 状态层与存档（1346–1453）

- `SAVE_VER = 2`，`localStorage["cs2_save"]`。
- **`restore(raw)` 是唯一入口**，四层校验：量纲（数值范围/长度上限）→ 引用白名单（`done`/`achv`/`owned`/`mjInvites` 必须在内容表里）→ 状态机边界（`active.shot` 越界丢弃）→ 子系统缺省补齐（旧档自动迁移）。坏档一律 `null`，绝不污染 UI。
- 存档点：状态变更 + 电影层每 4 s + `pagehide` + `visibilitychange`（4675–4677）。
- `S.active` 支持**中途退出原地续播**；导出/导入 JSON。
- 连续几个版本新增的字段（`mj*` 1389–1410、`bf*`、早餐店）都走"缺省即补"，是**向后兼容的存档演进**范式。

### 5.3 演出层（1581–1860）

```
playNode → 章节卡 → playShot（视频 → 剧照 Ken Burns → 动态渐变 三级兜底）
        → 交互（openInter 分发）→ after 补镜 → finishNode（XP/成就/章末卡）
```
加固件：`mediaToken` 递增令牌作废旧回调（视频与剧照都有）；首帧就绪才淡入；2.6 s 无画面锁死兜底；`probeMedia()` 启动自检 + 诊断面板。

### 5.4 音频层（982–1284, 2216–2260）

三层结构（音效 / 环境音 / BGM），核心是两条工程决策：

1. **文件优先、缺失回落程序化合成**（`index.html:987-988`）——素材没到位也照常发声，素材到位自动升级，调用点一行不用改。
2. **候选路径解析层**（`1004-1097`）——素材库同时存在 `sfx-` / `amb-` 前缀与无前缀两种命名。v1.24 基线实测：**64/65 条音效 + 9/9 条环境音永远取不到，且因为 `sfxFile()` 无条件 `return true`，连回落都没发生——彻底静音且不报错**。现在统一为"候选列表 + 三态（pending/ready/bad）+ 真把失败上报给调用方"，并配 `tests/audio-paths.test.cjs`（20 项）把这道缝焊死。

环境音还有一处细节：生成素材首尾电平差可达 55 dB，直接 `loop=true` 会在循环点"啪"一声，所以用**双元素交叉淡化**（`loopCrossfade`, 1140）盖住接缝。

配音：`voMode` 三态（真人原声 → 合成 TTS → 关），启动探测用 `loadedmetadata` 而非 `canplaythrough`（`2220-2224` 记录了早期因探测口径把"有配音"误判成"没配音"的踩坑）。

### 5.5 玩法层（1736–4124）

`openInter()`（1736）按 `type` 分发到 12 个实现；隐藏选项（`pre`）优先于常规交互。统一出口 `afterInter()` → `applyFx()` → `finishNode()`。

## 6. 子系统 A：`mahjong.js`（5,664 行）

### 6.1 契约与边界

- IIFE（27），单一全局 `window.Mahjong`（5433），`version = "ganma-2.0"`。
- 规格 API：`start(hostEl, opts)` / `isBusy()` / `dispose()` / `openLobby()` / `showInvite()` / `hideInvite()` / `rules{}`；`debug{}` / `test{}` 明确标注"不属于规格"（头注释 `:11`）。
- 宿主调用：`Mahjong.start($("mj"), {stake, style, state:S, invite, onFinish})`（`index.html:4197-4200`）。
- **宿主耦合点**：模块把宿主的 `S` 直接接进来，`applyOutcome` 原地改 `S`（`mahjong.js:570-620`）；模块自己给 host 加 `on` class 却刻意不摘（4928，注释说明由页面负责）；宿主另用 350 ms `setInterval` 兜底 + 自己调 `dispose()`（`index.html:4183-4187`）。这是**双重生命周期管理**，能跑但边界模糊。

## 13. 架构评估

### 13.1 做得好的地方（有证据，不是客套）

1. **"缺失即降级"贯穿三层**：画面三级兜底、音频文件→合成回落、模块缺失→提示跳过、WebGL 不可用→2D 沙盘。协作者不接素材也能打通全流程——这条纪律把"素材带外分发"这个最麻烦的约束变成了非问题。
2. **状态层的向后兼容范式**：`restore()` 一个入口、四层校验、新字段"缺省即补"，从 v0.6 到 v1.31 加了麻将/早餐店/打斗等大量字段，旧档从不判坏档。`tests/core.test.cjs` 里专门有"旧档缺字段仍是合法档、脏数据被清洗"的断言。
3. **注释写"为什么"，尤其写踩坑**：`index.html:1004-1013`（音效永久静音的真因）、`2736-2740`（判定条 2 帧不可瞄）、`breakfast.js:1134-1139`（55 dB 电平差导致循环爆音）、`.gitignore:1-18`（junction 与 git 的交互）。这些注释的价值高于文档。
4. **测试是"契约"而非"覆盖率"**：`window.__cs2` / `debug{}` 是显式契约；断言锁的是**语义**（一局 6–9 回合、连打必须优于直拳、立绘未就绪要能回落骨骼），不是实现细节。`tools/lib/raster.js` 让无头层能对真实绘制调用出 PNG，这是很罕见的做法。
5. **素材治理有法可依**：`SOURCES.md`（逐项授权）+ `媒体清单.json`（SHA256 契约）+ `link-media.ps1`（校验后挂接）+ `pack-media.ps1`（自产与第三方分流）。在"AI 生成素材大量涌入"的项目里，这套是稀缺的。

### 13.2 值得商榷的权衡

| 决策 | 收益 | 代价 | 判断 |
|---|---|---|---|
| 单文件内核（`index.html` 4,703 行 / 292 KB） | 双击即玩、零构建、`file://` 无 CORS 问题 | 单文件逼近可维护上限；必须靠 `patch-literal.js` 四道闸改代码 | **在"零构建 + 带外分发"约束下是对的**，但已到该拆的临界点 |
| 子系统自带 `<style>`（麻将）vs 样式全在宿主（早餐店） | 各自内聚 | 两种风格并存，新人要读两遍才知道样式在哪 | 建议统一到"宿主提供容器样式、模块只提供结构" |
| 玩法结果档位与效果解耦 | 新增玩法零改数据 | 效果分散在数据层的 `perfect/ok/miss` 与玩法实现之间 | 保持，这是本作最优雅的一处 |
| `Expect` 只告警 | 避免断言数增长就红 | **计数漂移无人管**（§11） | 应改为严格模式或自动读基线 |
| 主玩法另起一套（`fight2`） | 不破坏既有存档与 11 类玩法完整性、可 A/B 手感 | 双实现并存、旧代码要留很久 | 决策正确，但**需要显式的"退役条件"**（见 ADR-5） |

## 14. 演进建议

### 14.1 五条关键决策记录（ADR 式）

**ADR-1 · 修复并重新启用版本戳闸门**
*背景*：`--check` 现在退出 1；README 把 `build` 当作"看到旧戳就强刷"的判据。
*决策*：`node tools/dev/stamp.js` 重新盖章，并把 `--check` 接进 `run-all-tests.ps1` 作为**第 0 层**（失败即退出）。
*取舍*：每次改代码要多跑一条命令；换来"浏览器里跑的是不是最新代码"可机器判定。
*后果*：若坚持不接，应把 README 里对水印的承诺降级为"仅供参考"。

**ADR-2 · 把"数字"收敛成一处**
*背景*：同一套件的断言数在 4 个地方有 4 个值（§11）。
*决策*：套件启动时把实际用例数写进 `dist/test-results/*.json`；`run-all-tests.ps1` 的 `Expect` 改为"与上次产物比对，漂移超过阈值才告警"；文档删除手写数字，改为指向产物。
*后果*：文档不再需要人工同步；代价是首次运行要生成基线。

**ADR-3 · 素材缺失时单测 `skip` 而不是 `fail`**
*背景*：干净 clone 上 `tests/core.test.cjs` 必红（§12 P0-4）。
*决策*：一条素材都不存在 → `skip` + 说明"实拍素材不入库"；存在但只放了一半 → `fail`；`CS2_REQUIRE_MEDIA=1` 强制严格。
*后果*：新协作者第一眼是绿的；代价是"忘了放素材"不再被判失败（由 `link-media.ps1` 的 SHA256 校验承担）。

**ADR-4 · 三套素材计数统一到 `媒体清单.json`**
*决策*：其它文档只写"见 `媒体清单.json`"；修 `pack-media.ps1:94-95` 让 `video/poster/fx_*.jpg` 正确归类为 `original`（原创）。
*后果*：契约唯一；代价是每次素材变动要重新 `pack`。

**ADR-5 · 给双实现写"退役条件"而不是"择机清理"**
*决策*：在 `docs/` 建一张双实现清单（`fight` / `fight2`、旧听牌挑战 / `mahjong.js`），每条写清：谁在用、退役前提、退役后要改的测试。旧"麻将听牌挑战"（4124-4148）若无调用点，**下个版本就删**。
*后果*：避免"临时并存"变成永久债；代价是一次确认工作。

### 一句话总结

> 这套工程真正的资产不是 21 个节点或 12 类玩法，而是**"让 AI 能安全地持续改一个 300 KB 单文件游戏"的那套护栏**——版本戳、契约化测试、素材清单、补丁纪律。
> 护栏本身现在有两处松动（版本戳失效、断言计数失控），**修护栏的优先级高于加内容**。
