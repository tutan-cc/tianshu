> **分析视角**：产品（定位 / 用户 / 体验循环 / 内容盘点 / 现状诊断 / 指标 / 路线图），**不是**技术架构

## 0. 一页纸

| 项 | 结论 |
|---|---|
| **一句话定位** | 一个"重生逆袭"题材的**真人互动影游原型**：看真人短片 → 做抉择/玩小游戏 → 数值与九人羁绊变化 → 在沙盘上推进 Day0–Day9 |
| **当前阶段** | 可完整通关的**垂直切片**（序章 + 第一、二章），内容量 21 节点 / 57 镜 / 12 类玩法，**开发内部可玩，尚不具备对外发布条件** |

| **最大的产品风险** | **素材授权未核实**（`SOURCES.md`：全部实拍视频不得公开分发）—— 这是发布级阻断，且标题屏自己就写着这句话 |

| **如果只做三件事** | ① 清授权或换素材（发布前提）② 把调试入口从玩家视野里摘出去 ③ 加最小埋点，拿到第一份漏斗 |

## 1. 产品是什么

### 1.1 定位

**题材**：都市 · 重生 · 逆袭。主角陈默 32 岁加班猝倒，带着未来十年记忆回到 2015 年的 22 岁；一本【重生手册】（上一世的笔记本，夹着一页从没做到过的「恋爱守则」）是核心道具，暗线是"戴墨镜的人"和"顾曼为什么知道你是重生者"。

**品类**：真人互动影游（FMV / 互动影视）。玩家不是"操作角色"，而是"替角色做决定"——看片为主，玩法为辅。

**形态**：纯静态网页，双击 `index.html` 即玩，无需安装、无需联网、无需服务器。

### 1.2 差异化（相对同类）

| 维度 | 常见互动影游 | 本作 |
|---|---|---|
| 交互密度 | 以"选择支"为主，少量 QTE | **12 类玩法**，含完整麻将（赣麻规则、3 家 AI）、早餐店经营、回合制格斗 ×2 套、股市 K 线、谈判博弈 |
| 平台 | 客户端 / 主机 / 手游 | **浏览器单文件**，零安装、零依赖 |
| 内容基调 | 恋爱 / 悬疑为主 | **逆袭成长**：四维（财富/魅力/体魄/智慧）+ 九人羁绊双线，恋爱只是其中一条 |
| 本土化 | 泛化都市 | **赣麻麻将**（无吃无炮、抢杠、四档赔付 60/240/360/720）、早餐店、出租屋、1978 酒吧 |
| 制作方式 | 实拍团队 | 实拍素材 + **AI 生成美术/语音**（Lovart 出图、StepAudio 生成 300+ 条音频，含 4 席位麻将报牌），成本结构完全不同 |

> 产品含义：**玩法密度是差异化，也是成本结构的结果**——没有真人摄制预算去堆镜头，就用可程序化生成的玩法撑住游玩时长。这条策略在本作是成立的。

## 2. 目标用户与使用场景（假设，待验证）

| 画像 | 特征 | 为什么可能玩 | 顾虑 |
|---|---|---|---|
| **A · 互动影游老玩家** | 玩过《隐形守护者》《完蛋！我被美女包围了》 | 品类熟悉，看到"重生"题材愿意试；对"多结局/分支"有期待 | 本作目前**单线走向**（21 节点基本是一条链），分支在于数值与羁绊而非结局 → 可能觉得"选择不够重" |
| **B · 麻将/小游戏玩家** | 被"赣麻完整规则"吸引 | 麻将子系统是**真规则 + 3 家 AI + 报牌语音**，可以独立当小游戏玩 | 入口藏在剧情 D8 晚，新人要玩 40 分钟才碰到；自由局入口在侧栏，但**新手看不到** |
| **C · 同人/技术向玩家** | 对"单文件网页游戏 + AI 生产管线"感兴趣 | 零安装即玩，可改可拆 | 需要文档与可读代码（这部分很强：`tools/` + 9 篇 md） |

**使用场景**（从形态推导，可靠）：桌面 Chrome，一次 20–45 分钟的整块时间；移动端当前**不可用**（≤820px 直接隐藏侧栏，未做抽屉）。

> 建议用一次 5 人小样本试玩把上面三行"假设"变成结论——这是当前投入产出比最高的产品动作。

## 3. 核心体验循环

```
        ┌──────────────────────────────────────────────────────┐
        │  ① 看片：58 秒–2 分钟的真人镜头（可跳过 / 可回顾台词）│
        └───────────────┬──────────────────────────────────────┘
                        ▼
        ┌──────────────────────────────────────────────────────┐
        │  ② 做决定 / 玩：12 类玩法中的一种（10 秒 – 10 分钟）  │
        │     选择 · 答题 · QTE · 躲避 · 股市 · 取证 · 复原     │
        │     谈判 · 打斗 · 麻將 · 早餐店                        │
        └───────────────┬──────────────────────────────────────┘
                        ▼
        ┌──────────────────────────────────────────────────────┐
        │  ③ 立刻看到代价：数值 toast + 羁绊条 + 成就弹窗        │
        │     （四维 / 9 人羁绊 / flags 线索 / 装备 / 经验）     │
        └───────────────┬──────────────────────────────────────┘
                        ▼
        ┌──────────────────────────────────────────────────────┐
        │  ④ 回到沙盘：9 个地点 2D/3D 切换，氛围随剧情变色        │
        │     → 点发光地点进入下一节点（时间推进 Day→Day）        │
        └───────────────┬──────────────────────────────────────┘
                        ▼
              章末结算卡（CHAPTER ONE / TWO）→ 下一章
                        │
        ┌───────────────┴──────────────────────────────────────┐
        │  ⑤ 侧循环（可重复，随时可做）                          │
        │     🀄 找人打两圈（麻将自由局：注码/打法/口碑/情报）    │
        │     🍳 做份早餐（每日一次 × 9 人，涨羁绊）              │
        │     🎟 刮刮乐（¥20 一次，真 Canvas 刮开）              │
        └──────────────────────────────────────────────────────┘
```

**这个循环的设计优点**：反馈即时且**三层可见**（数值 toast → 侧栏羁绊条 → 成就）。玩家做完选择立刻知道"我变成了什么"，这是互动影游最核心的爽点，本作接得很实。

**这个循环的设计缺口**：
1. **没有"悬念钩子"的显式管理**。暗线（墨镜男 / 顾曼）散在节点里，但没有"当前未解之谜"面板——玩家容易看完就忘，第二章结尾的钩子力度被稀释。
2. **侧循环与主线的耦合是单向的**：麻将/早餐店 → 涨羁绊/口碑，但**主线几乎不引用侧循环的成果**（只有少量 flags / 邀约）。侧内容玩得再多，主线观感变化有限 → **侧循环的动机靠"好玩"而不是"有用"**。

## 4. 内容与系统盘点（产品语言）

### 4.1 叙事内容

| 项 | 值 |
|---|---|
| 章节 | 序章 + 第一章（Day0–Day6）+ 第二章（Day7–Day9） |
| 节点 | **21 个**（含 1 个开发验证节点 `brawl2`，见 §6.2） |
| 镜头 | **57 个**（42 分镜 + 15 补镜），全部真人实拍 + 2 段程序化动画（K 线 / 数据洪流） |
| 章末结算卡 | 2 张（第一章 / 第二章），带"第二章预告"钩子文案 |
| 剧本 | `docs/剧本-垂直切片.md`（含逐镜"台词 ↔ 实际画面"对照修订表） |
| 待接线 | 第三章及以后：墨镜男的老板 / 顾曼的身份（素材与接口已就绪） |

### 4.2 玩法矩阵（12 类）

| 玩法 | 节点 | 单次时长 | 挂钩属性 | 服务的产品目标 |
|---|---|---|---|---|
| 三选一选择 ×8 | 序章/房东/公园/公司/酒吧/妹妹/护士/大师 | 10–30 s | 全维度 + 羁绊 | **代入感与价值观表达**（主循环骨架） |
| 限时答题 ×2 | 图书馆·讲题三连 / 投资大厦·风口三连问 | 3×12 s | 智慧 | 智力型玩家的表现位 |
| 时机 QTE ×2 | 拳击馆·反击 / 金色年华·拼酒 | 6–15 s | **体魄/魅力加宽判定区** | 紧张感；让数值"手感化" |
| 躲避（数据洪流） | 老城区 | 12 s | 智慧加宽判定带 | 动作代入 |
| 股市波段（K 线） | 投资大厦 | ~60 s | **财富主线** + 顾曼羁绊 | 题材契合（重生=预知大势） |
| 线路取证 | 公司机房 | ~30 s | 智慧 | 悬疑段落 |
| 信号复原（记忆） | 出租屋 | ~30 s | 智慧 | 情感段落（前世之忆） |
| **谈判博弈** | 金色年华·合同桌 | 2–3 min | 魅力 + **红姐/顾曼羁绊直接换算成筹码与底线** | **羁绊系统真正接入玩法**的示范 |
| **打斗（回合制格斗）** | 老城区·一打二 | 2–5 min | 体魄 → 生命值 | 情绪爆发点（第一章章末） |
| **打斗 2.0（侧视对战舞台）** | 老城区·一打二（2.0 验证） | 4–8 min | 同上 + 体干/硬直/反击窗口 | 手感升级的 A/B 验证 |
| **麻将（赣麻完整规则）** | 金色年华·麻将局 + 侧栏自由局 | 5–10 min | 智慧 + 麻将席位由羁绊决定 | **可独立成产品的子系统** |
| **早餐店·拼手速** | 出租屋·早餐店开张 + 侧栏每日一次 | 75 s | 无（涨羁绊） | 轻量日常 + 九人羁绊的"主动经营"手段 |

**产品观察**：玩法采用"**数值决定难度，而不是难度选项**"的设计——体魄加宽绿区、智慧加宽判定带、装备/等级/消耗品改玩法参数。**没有难度选择菜单，难度就是你养成的结果**。这是好设计（让成长可感知），但代价是：**前期玩家会觉得"我操作不行"**，而实际是数值不够。建议在首次失败时显式提示"你的 XX 属性提高了判定宽度"。

### 4.3 成长与羁绊

| 系统 | 规模 | 产品作用 |
|---|---|---|
| 四维 | 财富 / 魅力 / 体魄 / 智慧 | 主数值；直接改玩法参数（非纯展示） |
| 等级 | 8 级 + 称号（重生者 → 命运之子），通关 +20 经验 | 长期正反馈 |
| **羁绊** | **9 人**：芳姐(房东)·苏晚晴(跑步女孩)·林溪(女同事)·温阮(考研女孩)·雷姐(拳击教练)·红姐(酒吧老板娘)·陈果(妹妹)·白露(夜班护士)·顾曼(投资人) | **本作的情感与策略核心**：谈判开局筹码、麻将席位、QTE/结局分支都接在这里 |
| 装备 | 6 件 / 3 槽（手/衣/饰） | 只产加成、不动四维（防数值膨胀） |
| 消耗品 | 4 种，**只 buff「下一场」**，用完即清 | 防刷数值的节制设计 |
| 商店 | 用财富购买 | 财富的出口之一 |
| 成就 | **18 枚** | 见下 |
| 线索 flags | 字符串数组 | 解锁隐藏选项（**不满足时灰显并写明原因，而不是隐藏**） |

**成就构成的产品含义**（18 枚）：

- 主线向：重生者 / 第一桶金预告 / 万人迷 / 一拳成名 / 兄妹同心 / 风口猎人 / 股神 / 身法 / 取证完毕 / 前世之忆 / 武装到牙齿 / 谈判高手 / 后巷立威
- **麻将侧内容：牌桌老千 / 三连胡 / 包赔三家 / 冤家（4 枚 = 22%）**
- 早餐店：早餐店老板（1 枚）

> **22% 的成就来自麻将侧内容**——说明麻将被当作"第二主玩法"在运营。若目标用户是 A 类（影游玩家），这个配比偏高；若是 B 类（麻将玩家），则应该在**更早的节点**就把麻将介绍给玩家（现在第一次遇到是 D8 晚，约 70% 进度处）。

### 4.4 侧内容循环（可重复，本作的"留存资产"）

| 侧循环 | 触发 | 频率限制 | 产出 | 复玩动机 |
|---|---|---|---|---|
| 🀄 找人打两圈 | 侧栏常驻 | 无（消耗财富注码） | 财富 / 口碑 / 连胡记录 / **情报** | 麻将本身好玩 + 8 张邀约卡各有剧情后果（放水/认真会结梁子） |
| 🍳 做份早餐 | 侧栏 + D7 剧情 | **每日一次 / 每人** | 羁绊 +6~+10（失败 −3~−6） | 好感度是通关与分支的硬通货 |
| 🎟 刮刮乐 | 侧栏常驻 | ¥20 / 次 | 财富（¥0/5/10/20/50/200） | 即时反馈 + 赌性 |

> 这三个侧循环是**当前产品最被低估的资产**：它们把"20–45 分钟的一次性体验"变成"可以反复回来的小游戏集合"。但它们的入口（侧栏三个按钮 + 麻将邀约）**没有任何引导**，且与主线成就体系耦合弱。

### 4.5 表现与音频

| 项 | 现状 |
|---|---|
| 画面兜底 | 视频 → 剧照（Ken Burns 推进）→ 动态渐变。**素材全缺也能通关** |
| 沙盘 | 9 地点 2D SVG ↔ 3D 等距（Three.js）；氛围随剧情切 calm/city/tense/night/dark；WebGL 不可用自动回落 |
| 音频 | **全部自产**：配音 54 条（分角色音色）· 麻将报牌 45 条 × 4 席位各一套 · 早餐店语音 15 条（另有 79 条归档在 `audio/bf/_unused/`）· 音效 65 · 环境音 9 · BGM 5 情绪（实时合成兜底） |
| 音色策略 | 早期用"演员原声"，因**声画台词不一致**改为 TTS；`SOURCES.md` 记录了这一取舍 → 产品上是"字幕为权威文本，配音提供人声质感" |
| 质感层 | 胶片颗粒 / 扫描线 / 暗角 / 章节卡转场 / 打字机字幕 / 台词回顾（200 条） |

### 4.6 存档与平台

- 单档位，`localStorage`，自动存档（状态变更 / 每 4 秒 / 切后台 / 关页），支持**中途退出原地续播**、导出/导入 JSON。
- 平台：桌面 Chrome 最佳；移动端未适配（≤820px 隐藏侧栏）。
- 无账号、无云存档、无服务端。

## 5. 体验曲线（按时间轴看玩法分布）

| 时间 | 节点数 | 玩法 | 节奏观察 |
|---|---|---|---|
| Day0 夜（序章） | 1 | 选择 | 开场即抉择，代入快 |
| Day1–Day3（第一章前段） | 6 | 选择×4 · 答题 · QTE | 选择密集，建立人物关系 |
| Day4–Day6（第一章后段） | 2 | 取证 · 躲避 | 悬疑 + 动作 |
| **Day6 晚（章末）** | **2** | **打斗 ×2（新版不可达）** | ⚠ 沙盘只认首个可用节点，玩家永远进旧打斗，见 §6.2 B4 |
| Day7（第二章开） | 4 | 选择 · **早餐店** · 记忆 · 选择 | 情感线回暖，引入日常玩法 |
| Day8 | 4 | 股市 · 答题 · 选择 · **麻将** | 财富线高潮 + 麻将首秀 |
| Day9（章末） | 2 | **谈判** · 拼酒 | 双压轴：话术 + 手感 |

**观察**：
1. **前 15 分钟全部是"选择"**（Day0–Day3 共 7 个节点里 5 个是选择），玩家在还没体验到"玩法多样性"之前，就已经形成了"这是个点点点的游戏"的第一印象。**建议把一个小玩法前置到 Day1–Day2**。
2. **麻将首秀在 D8 晚**（约 70% 进度），但它承载了 22% 的成就和主要的可重复内容——**位置与权重不匹配**。
3. 章末（D6 / D9）都用了"高刺激玩法收尾"，节奏设计是对的。

## 6. 现状评估

### 6.1 强项（有证据）

| # | 强项 | 证据 |
|---|---|---|
| 1 | **玩法密度撑住了时长**：21 次交互 / 12 种玩法类型 | 数据层实测（8 次选择 + 10 种不同小游戏） |
| 2 | **数值"手感化"**：属性直接改判定窗口/判定带/本金/生命 | `FIGHT2_MOVES`、躲避判定带随智慧、QTE 绿区随体魄 |

## 8. 商业化与合规

### 8.1 现状

**当前无任何商业化设计**：无内购、无广告、无付费点。侧栏的 "¥" 是**游戏内货币**（财富），与现实无关。`刮刮乐（¥20）` 容易引起误读，建议在 UI 上明确"游戏内货币"。

### 8.2 三条可能路径与取舍

| 路径 | 前提 | 收益 | 代价 |
|---|---|---|---|
| **A · 免费试玩 + 完整版买断** | 清授权 or 全换自制素材；第三章做完 | 与品类惯例一致（影游普遍买断 20–40 元） | 需要一次性做完 3 章 + 平台（Steam/WeGame）上架成本 |
| **B · 免费网页 + 侧内容留存** | 素材合规；移动端适配 | 传播成本极低（打开网页即玩），麻将/早餐店做裂变入口 | 变现难；网页游戏的付费意愿低 |
| **C · 保留原型，作为技术/产能展示** | 无需清授权（不公开投放） | 零风险；可作为"AI 生产管线"的能力证明 | 无直接收益 |

> **建议**：短期走 **C → B**（先把网页版做成能公开分享的形态，素材逐步替换为 AI 自制），中期再决定是否投入 A。**核心理由**：本作最强的资产是"AI 生产管线 + 高玩法密度"，而不是真人素材——沿着自己的成本优势走，比追平实拍影游的质感更现实。

### 8.3 合规要点

## 9. 指标体系与最小埋点方案

### 9.1 North Star 与分层指标

| 层 | 指标 | 为什么 |
|---|---|---|
| **North Star** | **单周目完成率**（走完 21 节点 / 开始游玩的玩家） | 影游的核心价值是"看完一个故事"；不如"时长/DAU"容易被小游戏侧内容刷高 |
| 激活 | 首屏 → 序章完成率 | 检验开场 3 分钟是否留人 |
| 过程 | 各节点**流失率**（尤其 D6 打斗、D8 麻将） | 找卡点；规则型玩法最可能劝退 |
| 过程 | 各玩法**首次通过率 / 平均尝试次数** | 判断难度是否合理（区分"手残"与"数值不够"） |
| 参与 | 侧循环使用率（麻将/早餐店/刮刮乐 至少用过一次的比例） | 验证侧内容的价值 |
| 留存 | D1 / D7 回访（有存档的玩家） | 侧循环是否形成回访动机 |
| 质量 | 素材兜底触发率（走了剧照/渐变的比例） | 直接反映素材分发是否到位 |

### 9.2 最小埋点集（不引入任何第三方 SDK）

在 `localStorage` 里维护一个环形缓冲（比如 500 条），事件只记 5 类：

```js
{ t, ev, node, type, result, ms }   // ev: start|shot_end|inter_end|node_end|side_loop
```

- `inter_end` 带 `result`（perfect/ok/miss/win/lose）与耗时 → **一次试玩就能算出所有玩法的首次通过率与卡点**。
- 导出方式：复用已有的「导出存档」按钮，多导出一个 `cs2_metrics` 键即可（零后端）。
- 隐私：纯本地、无个人信息、不上传 —— 这也符合当前"不联网"的形态。

> 这是本报告**投入产出比最高的一条建议**：约半天工作量，把"全靠手感"变成"有据可依"，而且不破坏零依赖架构。
